# Перевод Dis в C

`dis2c` переводит Dis-файлы от обоих компиляторов Limbo в C99. Полученный код
связывается с соответствующей средой Inferno: адресация операндов раскрывается
в C, простые пересылки и модульная целочисленная арифметика генерируются напрямую,
остальные операции вызывают существующие функции VM. Сборка мусора, каналы,
исключения и загрузка модулей используют штатную среду исполнения.

Это начальный AOT-бэкенд с поддержкой среды Inferno. Самостоятельный исполняемый
файл, зависящий только от libc, пока не генерируется.

Из корня репозитория:

```sh
make -C utils/dis2c
utils/dis2c/dis2c --check program.dis
utils/dis2c/dis2c -n program_aot -o libinterp/program_aot.c program.dis
```

Для сборки утилиты нужны C99-компилятор и GNU make. Python нужен только для
тестов и обновления таблицы опкодов. При нескольких модулях задавайте разные
префиксы через `-n`.

Добавьте `program_aot.$O` в `OFILES` файла `libinterp/mkfile`, объявите
`int program_aot_register(void)` и вызовите её при инициализации выбранной
платформы, до загрузки модуля. Проверьте возвращённое значение. Регистрация
выполняется до запуска интерпретатора либо под блокировкой VM. Затем пересоберите
`libinterp` и эмулятор. Обычный `load` будет выбирать C-код для точного исходного
Dis-файла. Сгенерированный объект должен оставаться загруженным всё время работы.

Функция `Module *program_aot_load(char *path, Dir *dir)` позволяет C-встраиванию
загрузить встроенный образ через штатный `parsemod`; оба аргумента обязательны.
Правила владения объектами и блокировки остаются правилами загрузчика Inferno.

Полное совпадение байтов защищает от применения устаревшего перевода. Изменение
кода, данных, подписи или метаданных требует повторной генерации. Подписи
проверяет штатный загрузчик. `dontcompile` и `DONTCOMPILE` отключают подключение;
зарегистрированный перевод удовлетворяет `MUSTCOMPILE`.

Dis-формат не изменён. Структура `Module` расширена полем `cstep`, поэтому среду
и сгенерированные объекты нужно пересобирать вместе. Сохраняются Dis-счётчик
команд, таблицы исключений и квантование по инструкциям. Можно смешивать C-модули
и интерпретируемые модули. Ограничения текущего ABI VM сохраняются; новые JIT для
x86-64, arm64 и riscv64 эта работа не добавляет. Ускорение пока не гарантируется.

Пример модуля и интерпретируемого вызывающего кода находится в `examples`.
Команды сборки, подключение, ограничения и точный охват тестов описаны в
[README.md](README.md).

```sh
make -C utils/dis2c test
```

Тесты проверяют сгенерированный C на настоящих заголовках и используют код
загрузчика, декодера и цикла исполнения VM. Для сложных операций проверяется
выбор обработчика; полноценный запуск всех их побочных эффектов и загрузка всей
Inferno этим тестом не заменяются. Переменная `LIMBO` включает дополнительную
проверку компиляции примера из исходного Limbo при наличии рабочего компилятора.

Адресация в новом сгенерированном C использует проверенные `decaddress` и
`decindirect` из `dec-addr.h`. Для 16 простых команд сохраняется прямой C-путь,
но слоты читаются и записываются без предположений о выравнивании, с проверками
диапазонов и поддержкой перекрытия. Сложные команды вызывают штатные обработчики.
Старые сгенерированные файлы следует пересоздать вместе с соответствующей средой.
[Проверки WORD32/WORD64 и воспроизведение ошибок](tests/README.native-slots.md).
