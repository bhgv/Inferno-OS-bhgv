# String case в доверенном LP64-модуле

Продолжение числовых таблиц: компилятор описывает `ICASEC` с одиночными
String-метками, включительными диапазонами и default. Частный конструктор
создаёт настоящие строки через переданную владельцем length-aware фабрику
`String *(*)(char *, int)`. Стенд использует настоящий `c2string` runtime.
Фабрика возвращает одну принадлежащую вызывающему ссылку; nil/H запрещены.

## Раскладка и владение

Счётчик и цели остаются Word32, ссылки на String занимают восемь байт.
После счётчика с padding идут строки low/high/target/padding размером 24 байта,
затем default. При нуле строк размер таблицы равен восьми байтам; иначе
`12 + 24*n`. У singleton high равен H, но его ячейка всё равно входит в
карту ссылок. Заголовки, цели и padding в карту ссылок не входят.

До выделения памяти проверяются точная карта MP, роли операндов,
выравнивание, границы таблиц и глобальных строк, валидность UTF-8,
упорядоченность непересекающихся диапазонов, локальные цели функций и
запрет перехода внутрь островков вызова. Лимиты: 4096 строк на таблицу,
4096 байт на литерал и 1 MiB суммарного текста. Встроенный NUL допустим:
всюду передаются явные длины. Дополнительные записи обычных глобальных
String не могут перекрывать таблицы или друг друга.

Конструктор немедленно помещает каждую созданную String в уже закреплённую
ячейку MP. Отказ следующего выделения освобождает предыдущие владельцы.
Точные алиасы одной таблицы в одной функции создают владельцев однократно;
алиасы между функциями запрещены из-за разных локальных координат целей.
Клонирование MP использует настоящие карты и retain runtime. Исходные
буферы метаданных после успешного построения больше не нужны.

## Выполнение и границы этапа

Частное поле Module выбирает C predecode для смешанной таблицы. Он проверяет
фактический FP/MP, карту ссылок и полный диапазон выбранного Inst, ищет через
настоящий `stringcmp`, затем публикует PC. Поиск не выделяет память и не
уступает управление; ошибка сохраняет полный REG. Поддерживаются ASCII,
Rune, Unicode, nil как пустая строка и встроенный NUL.

Окружающие функции и вызовы исполняются как интерпретатором, так и JIT.
Сам поиск String на этом этапе выполняет C; нативный String-search emitter
ещё не реализован. Новый callback и структуры — частный API доверенного
конструктора. Файловые section/opcode IDs не добавляются, загрузчики старых
профилей не получают общего допуска таблиц. Старые 32-битные пути сохранены.

## Проверки

```sh
python3 utils/tests/native64-typed-string-tables.py --limbo /path/to/limbo
ASAN_OPTIONS=detect_leaks=0 \
NATIVE64_CFLAGS='-O1 -g -DNDEBUG -fno-strict-aliasing -fsanitize=address,undefined -fno-sanitize-recover=all' \
  python3 utils/tests/native64-typed-string-tables.py --limbo /path/to/limbo
```

Реальные Limbo `choose`, `global`, `size` и соседняя функция проверяются
независимо по старому Dis: байты литералов, карта, цели и смещение всех функций
на одну инструкцию. 1728 межмодульных запусков варьируют C/JIT обеих сторон,
рост стека, кванты 1/3/1000 и представление ASCII/Rune. Проверяются результаты,
защитные байты, независимые MP и полное освобождение владельцев.

Дополнительно проходят 16 отказов метаданных до выделения памяти,
34+35=69 позиций отказа конструктора, две копии MP, точные алиасы, порча
заимствованных буферов, четыре полных снимка REG при ошибках и поиск по
идентичному объекту при повреждённом неиспользуемом default. Активные контроли
удаления UTF-8-проверки и retain при клонировании обязаны обнаруживать ошибку.
Весь новый тест проходит ASan+UBSan с NDEBUG и detect_leaks=0.

Предшествующая числовая матрица завершилась успешно на x64, ARM64,
Android ARM64/Bionic и RV64. Новый String-тест включён девятым обязательным
тестом в ту же матрицу; её результаты подтверждаются отдельно.
Проверка полного стартового набора AWM принимает 16 тел и отклоняет 344
целиком, включая новое принятие `appl/cmd/sh/sh.b:redirstr`. Это проверка
компилятора; инструкции полного AWM пока не выполняются. Следующие этапы —
связанный граф импортов и его запуск через Limbo `load`/`init`, расширение
поддержки оставшихся операций и нативный поиск строк.

Исполнение импортов через глобальную модульную ссылку в MP проверяется
[следующим этапом](native64-typed-string-imports.ru.md).
