# Арифметика и преобразования в файловом клиенте Dis64

[English version](dis64-client-numeric.md).

Клиент загружаемого модуля теперь выполняет арифметику `real` и преобразования
между `int`, `big`, `real` до и после вызовов. Сохраняются ограничения
[клиента с управлением потоком](dis64-client-control-flow.ru.md): один void-вход
без аргументов, одна библиотека/интерфейс/путь и скалярные сигнатуры импорта.
Обычный вход AWM с context/list и общая компиляция управляемых модулей ещё нужны.

## Полный пример

`library.m`:

```limbo
Library: module {
    PATH: con "/demo/library.dis64";
    inc: fn(n: int): int;
};
```

`library.b`:

```limbo
implement Library;
include "library.m";
inc(n: int): int { return n+1; }
```

`client.b`:

```limbo
implement Client;
include "library.m";
Client: module { init: fn(); };
init() {
    m := load Library Library->PATH;
    if(m == nil)
        return;
    first := m->inc(7);
    a := 3;
    b := 2;
    x := real a;
    y := real b;
    fraction := x/y;
    rounded := int fraction;
    argument := first+rounded;
    last := m->inc(argument);
    if(last != 11) {
        zero := 0;
        bad := 1/zero;
    }
    keepx := x;
    keepy := y;
    keepfraction := fraction;
}
```

Создайте `/demo` внутри корня эмулятора и соберите:

```sh
limbo -64b -I . -o /path/to/root/demo/library.dis64 library.b
limbo -64c -I . -o /path/to/root/demo/client.dis64 client.b
emu -r /path/to/root -X dis64-calls -c 1 -d /demo/client.dis64
```

`-c 0` выбирает интерпретатор. Пример завершается без вывода; неверный результат
попадает в условное деление на ноль. Преобразование `int fraction` округляет 1.5
до2, поэтому получается 8+2+1. Подключать Sys для печати здесь не требуется.

Этот файловый профиль пока резервирует MP под корни библиотеки и путь. Получайте
Real из скалярных локальных переменных, как в примере: произвольные константные
DATA-записи Real/Big пока не поддержаны. Разные типы должны занимать разные живые
ячейки. Повторное использование одного восьмибайтового места как Big, а затем
Real отвергается. Последние копии в примере сохраняют время жизни переменных.
Аргумент вызова предварительно вычисляйте в локальной переменной: выражение,
встроенное в остров подготовки кадра, остаётся отдельным ограничением.

## Операции и поведение VM

| Операция | Вход | Результат |
| --- | --- | --- |
| `+`, `-`, `*`, `/` | Real, Real | Real |
| Унарный `-` | Real | Real |
| `big word`, `real word` | Int | Big, Real |
| `int wide`, `real wide` | Big | Int, Real |
| `int fraction`, `big fraction` | Real | Int, Big |

Проверяются формы с неявным левым операндом в назначении и с тремя явными
операндами. Составное присваивание и арифметика над Real, возвращённым файловым
модулем, работают через существующие C-обработчики и JIT. Возвращённый Big можно
преобразовать в Real и передать результат последующему Big-вызову. Загрузка
библиотеки по-прежнему сама не вызывает её `init`.

Существующая VM округляет половины от нуля: 1.5 становится2, -1.5 становится-2.
Real-to-integer проверяет диапазон и конечность округлённого значения до записи
результата; ошибка — `invalid argument`. В новых исходных примерах исполняются
конечные значения вне диапазона Int и Big. Новое покрытие NaN/Infinity или
FP-окружения этим не заявляется. Big-to-Int сохраняет младшие биты Word32:
проверяются `(1<<40)+7`, дающий7, и отрицательное значение. Big-to-Real сохраняет
обычные ограничения точности существующего преобразования.

Типы источника и назначения выводятся отдельно. Восьмибайтовый Big нельзя читать
как Real только из-за одинаковой ширины. Арифметика требует Real, а каждый вход
должен быть определён на всех входящих путях CFG. Непосредственные Real/Big,
чтение MP, доступ к подготовленному кадру, пересечения, скрытый средний аргумент
и запись поверх другого типа отвергаются до создания runtime-модуля. Новых
опкодов, видов сигнатур или секций нет.

## Повторение проверок

```sh
python3 utils/tests/dis64-scalar-client.py --numeric --limbo /path/to/limbo
python3 utils/tests/dis64-scalar-client-boot.py --numeric \
  --limbo /path/to/limbo --root /path/to/root --emu /path/to/emu
python3 utils/tests/dis64-scalar-client-numeric-proof.py --limbo /path/to/limbo
python3 utils/tests/dis64-scalar-client-numeric-producer.py \
  --limbo /path/to/limbo --baseline /path/to/prior/limbo
```

Для ARM64 используются обычные `CC`, `NATIVE64_ARCH`, `NATIVE64_RUNNER`; у boot-
драйвера отдельный `--runner`. Общая проверка native-порта включает выполнение,
независимую проверку файлов и три контроля с удалением существенных условий.
Без необязательного `--baseline` producer проверяет детерминизм и наличие всех
новых операций; с ним также сравнивает байты прежних файлов. ASan/UBSan относятся
к проверке файлов и созданию/освобождению объектов, не ко всей исполняющейся VM.
Результаты Linux/QEMU не означают готовый Android GUI APK или запуск на устройстве.
