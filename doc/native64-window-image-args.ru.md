# Window.img и аргументы локальных вызовов native64

Компилятор поддерживает передачу Wmsrv.Window.img в импортированный аргумент Image и Wmsrv.Window.tag в String-аргумент локального вызова. Используется существующая роль 125. Проверяется полный канонический Wmsrv.Window: tag/r/img, classic 24 байта, native 32 байта, точные имена, типы и GC-карта. Смещение img — classic 20, native 24; tag — 0.

При чтении w.img.r/clipr для импортированного аргумента Image временно удерживается в compiler-owned FP root-слоте. Роль 166 расширена с Screen.fill (native 16) на Window.img (native 24). Сразу после копирования Point/Rect требуется очистка этого слота через nil. Загрузчик до выделений проверяет карты GC, порядок prep/copy/clear, единственный внешний call site и границы аргумента. Старые роли Screen.fill и локального Screen.image сохранены.

Также разрешена передача Draw.Wmcontext.ptr в channel-аргумент: классическое смещение 4 преобразуется в native 8. Проверяются все семь полей канонического Wmcontext, включая типы содержимого каналов. Другие поля Wmcontext этим расширением не открываются.

Новый utils/tests/native64-window-image-args.py проверяет 14 Limbo-функций, неизменность classic Dis и независимый oracle (114 повреждений). Runtime-проверка: 1056 сценариев C/JIT, FP/MP, local tag и ptr, четыре половины r/clipr, повторные вызовы, nil Window/Image/channel/tag, ошибки вызываемой функции, границы Word32, смена quantum, рост стека и полное освобождение ссылок. Проверяются 152 повреждения метаданных до выделений и все точки отказа создания модуля (40/41 C/JIT). Три активных контроля: неверный Image-получатель, пропущенная очистка временного слота и неверное смещение ptr. Image.origin в тесте — управляемый callback с настоящим сгенерированным Draw ABI; Draw-сервис не запускается.

В настоящем appl/wm/awm.b dragwin принята целиком. handlerequest проходит вызов dragwin на PC607 и останавливается на PC618 multi-call: подготовка Point из int hd args для локального sizewin. Сама sizewin пока останавливается на PC901 load-byte-array-class. awm.init остаётся на PC303 multi-callee. Графическое окно AWM и Android UI ещё не запущены; 32-битный код сохранён.
