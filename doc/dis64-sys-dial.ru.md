# Sys dial в приватном файловом профиле Dis64

[English](dis64-sys-dial.md). Поля, status и обмен данными описаны в [расширенном профиле Connection](dis64-sys-connection.ru.md). Это дополнение существующего Inferno с JIT,
без переноса DisVM и без реализации RPC-прокси.

`limbo -64l` теперь принимает ограниченный модуль с пустым входом, загрузкой
`$Sys` и полными вызовами `dial(string, string): (int, Connection)`:

```limbo
implement DialTrial;
include "sys.m";
DialTrial: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    (status, connection) := sys->dial("tcp!127.0.0.1!12345", nil);
}
```

Поднимите TCP-сервер на этом порту. Компиляция:
`limbo -I module -64l -o /build/dial.dis64 dial.b`. Запуск:

```sh
/build/emu/Linux/o.emu-g -v -c 0 -r /build \
    -d /dial.dis64 -P '$Sys' -X dis64-managed-trial
```

Повторите с `-c 1` для запроса JIT. Успешный запуск не доказывает исполнения
каждой операции машинным кодом. Сервер принимает соединение и видит EOF после
завершения модуля. Обычная настройка namespace консоли подключает IP-устройство
к `/net`. Пример ничего не печатает и закрывает результат при завершении.
Отказ native dial возвращает status -1 и пустой Connection.

Пока допускаются до 32 вызовов, непосредственные строковые литералы/nil,
повторное присваивание тем же `(status, connection)` и повторная загрузка Sys
между вызовами. Tuple имеет корни GC, C-результат проверяется owning-тестами.
Последующее чтение его полей/status в выражениях Limbo, смешанные импорты,
ветвления и произвольные ADT ещё вне этого ограниченного producer. Дополнительные
эффекты отклоняются, а не теряются при компиляции. Это ещё не общий shell/AWM
и не готовый Android GUI-клиент.

## Кадры и владение

| Область | Размещение |
| --- | --- |
| Вызывающий кадр | 112 байт, точная карта `00 dc` |
| Корни аргументов | String FP64 и FP72 |
| Результат | Word status FP80, немаркированное заполнение FP84..87 |
| Корни Connection | FD FP88, FD FP96, String FP104 |
| Native-кадр | 80 байт, карта `00 c0`, строки на 64/72 |
| Заимствованный адрес результата | Полные восемь байт на offset 32 native-кадра |

`native64diallea8step` допускает только эту геометрию. Старый binder для Word/FD
сохраняет прежние ограничения. Загрузчик проверяет полную последовательность
и приватное структурное дерево tuple до выделения памяти. Затем разрешаются
настоящая generated entry `dial` и legacy hash, используются обычные
LOAD/linkmod/MFRAME/MCALL. LOAD не вызывает init. Native startup Sys теперь
выбирает 23 экспорта; отдельная файловая группа String/Word/FD/array сохраняет
свои 14 сигнатур. Приватный tuple witness `0x77` не назначает публичного kind/ABI.

C-обёртка сохраняет кадр, адрес результата и прежний Connection до conversion
и release. Новый приватный внешний корень удерживает частичные FD/FD/String
при вложенных выделениях и callback очистки. Все три ссылки передаются в корни
результата до снятия временного корня. При ошибке новые raw/managed дескрипторы
закрываются, временный корень снимается, прежний managed tuple сохраняется.
Status после native-вызова уже может быть -1: общей атомарной транзакции над
32 байтами нет. Native-отказ очищает старый tuple.

Это исправляет пробел GC в `makeconnection`: первый созданный FD прежде
оставался только на C-стеке, пока очистка следующего выделения отпускала VM.
Общий C helper также используется announce/listen, но их файловый Dis64-вызов
этим изменением не включён. Используется существующий контракт Inferno
exclusion/ptradd; приёмка конкурентного GC адаптера FlashVM остаётся у него.

## Проверки

```sh
python3 utils/tests/dis64-sys-fixed-gc.py --limbo /host/tools/limbo
python3 utils/tests/dis64-sys-dial.py --limbo /host/tools/limbo \
    --root /build --emu /build/emu/Linux/o.emu-g
```

Owning gate использует настоящие инструкции VM, линкер, GC, generated-кадры,
Sys_dial и очистку FD с контролируемой native-границей: 16 C/JIT сценариев,
16 отказов stage/FD/String, повреждённые tuple/root/address/signature и откат
частичного построения. Проверяются status, заполнение, замена, прежние владельцы
и баланс ресурсов. Контрольное удаление проверки tuple roots/result address
должно провалить admission control. Консольный gate открывает 70 настоящих
loopback TCP-соединений с запросами C/JIT, проверяет EOF после замены/завершения
и отказы повреждённых файлов до планирования. Он включён в общий paired-console gate.
