# Владеющий нативный модуль и реальные экспорты

[English version](dis64-typed-modules.md).

После [нескольких вызовов в теле](dis64-typed-multiple-calls.ru.md) добавлен
сборщик полного ограниченного Module из проверенных таблиц компилятора:
Type, общий код, локальные переходы/вызовы, MP, экспорты, вход и leaf JIT.

```sh
python3 utils/tests/native64-typed-module.py --limbo /path/to/host/limbo
```

Для ARM64/Linux QEMU используются прежние CC/NATIVE64_ARCH/NATIVE64_RUNNER.
Набор включён в native64-port.py. Отдельная проверка сборки/отката на хосте:

```sh
ASAN_OPTIONS=detect_leaks=0 \
NATIVE64_CFLAGS='-O1 -g -fno-strict-aliasing -fsanitize=address,undefined -fno-sanitize-recover=all' \
python3 utils/tests/native64-typed-module.py --limbo /path/to/host/limbo --construct-only
```

Она создаёт/компилирует код без исполнения стековых ошибок VM. Runtime проходит
UBSan; прежнее ограничение runtime-ASan unwind остаётся открытым. LeakSanitizer
в этом окружении отключён, но явный баланс аллокаций и pin обязателен.

## Сигнатуры из Limbo

Частный multi-отчёт теперь содержит signature из штатного sign(Decl*) и
export_name, включая Box.identity для метода ADT. Это существующий32-битный
хэш интерфейса Limbo. Независимый reader читает обычный .dis и сопоставляет
имя, PC, дескриптор и хэш каждого экспорта. В основном наборе24 функции,
23 публичных экспорта и один скрытый помощник. Скрытый помощник доступен
локальному CALL и не появляется во внешней таблице. ADT-квалификация проверена
отдельным исходником; повреждённый хэш отчёта отклоняется.

## Сборщик и владение

Native64ModuleSpec задаёт неизменяемые читаемые C-таблицы: код/раскладки функций,
видимость/хэши/имена, локальные участки с индексами callee, MP-карту и начальные
скаляры. Поддержаны payload шириной1/4/8 байт; записи выровнены, не перекрываются
и не затрагивают GC-корни. heapz задаёт нули скалярам и nil ссылочным ячейкам.
Графы начальных String/array/ADT пока этим API не создаются.

До аллокаций проверяются размеры, карты, имена, цели и записи данных. Затем
копируются имена/карты/код/payload, связываются адреса, формируются экспорты
с sentinel и выбирается доверенный cstep. Ошибка инструкций при материализации
попадает в защищённый откат. REG и пустой выход сохраняются.

```c
Native64ModuleOwner owner = {0};
if(!native64typedmodule(&spec, wantjit, &owner))
    return 0;
/* owner.module — собственный незарегистрированный Module.
 * Держите owner по этому адресу до завершения всех экземпляров/стеков. */
if(!native64typedmoduleclear(&owner))
    return 0;
```

Owner держит ссылку Module и pin исходного MP, пока модуль вне общего реестра.
MP получает владельца до потенциально падающего выделения pin. Owner нельзя
копировать: идентичность проверяется до чтения указателя скопированного модуля,
включая копию после очистки оригинала. Очистка пустого owner идемпотентна и
отказывает, пока другие экземпляры/стеки удерживают Module. Это доверенный C-
контракт, не аутентификация указателей, конкурентный pin/ABA или постоянный отзыв.

Сборщик ничего не добавляет в namespace/cache и не выбирается файловым флагом.
Не помещайте эти частные owner в обычный кэш модулей: допуск и совместимость ABI
ещё требуют отдельной интеграции. Временные структуры и частично собранные
экспорты/Type/код/MP/JIT очищаются при отказе.

## Межмодульный вызов

Проверка использует штатные destroylinks, linkm, newmp, MFRAME, MCALL и RET.
Внешний consumer пока задаётся на C; provider целиком собран из тел компилятора.
Consumer/provider независимо выбирают C/RX с обычными Dis PC. Это существующий
одинаковый compiled-mode с независимыми leaf JIT, без нового native-PC перехода.

linkm находит экспорт по точному имени/хэшу, MFRAME выделяет его кадр,
прежний cstep связывает полный адрес результата, MCALL переключает Module/MP,
RET восстанавливает consumer. Два экземпляра provider имеют независимые MP.
Тестовый seed1234 в шаблоне и неактивном клоне позволяет заметить чужую запись;
void-код меняет только активный клон. Seed задаёт C-тест, это не общий разбор
инициализаторов обычного Dis. Неверное имя/хэш и скрытый helper не меняют import.

## Проверки и границы

На x64 и ARM64/Linux QEMU проходят по960 межмодульных случаев:768 обычных и
192 частных ошибок после получения управляемого результата. Покрыты четыре
сочетания C/RX, рост, вложенные исходные вызовы, кванты и значения. Проверяются
результаты/соседние байты, восстановление MP, шаблон/неактивный MP и полная
очистка владельцев. String/list identity передают непрозрачные владеющие графы;
настоящие операции строк/списков/Unicode/GC имеют прежние отдельные проверки.

Последовательно сломаны все58 C и59 JIT точек аллокации сборщика, включая pin/JIT.
8 отказов метаданных не выделяют память; ошибка кода откатывает уже выделенное.
Проверены байты примитивных payload и пустой MP. Четыре удалённых условия
(owner-copy, роль GC, очистка pin и хэш) ловятся точным смысловым диагнозом;
crash/timeout/sanitizer failure не засчитывается. Constructor-only проходит
host ASan/UBSan, ARM64 runtime — UBSan. Pin/OS/collector ограничены тестовой
границей; конкурентного сборщика этот набор не доказывает.

Перенос внешнего MCALL из исходников и общий управляемый writer/loader ещё
впереди. Публичные ID, Frame/Module, обычный байткод и LEA не меняются.
AWM остаётся14/346; сохранены байты16 исходников,376 раскладок и191 прежнего
образа. Запуск Android/Bionic, AWM и готовый GUI APK пока не заявляются.

Для библиотеки без entry сохраняются entry=nil и entryt=nil; сборщик не
создаёт искусственный init и ничего не запускает после загрузки. Частный
C-manifest обозначает отсутствие входа значением ~0U, полученным из -1
обычного заголовка Dis. Начало команды запуска остаётся отдельным решением caller.

Отдельный Limbo-клиент компилирует `load Multi` по `.m`-интерфейсу. Все16
сериализованных сигнатур импортов совпадают с экспортами поставщика; C-клиент
в runtime-проверке использует именно эти независимо полученные хэши.

Продолжение: [внешние вызовы из Limbo](dis64-typed-external-calls.ru.md).
Внутренние функции клиента теперь получены из исходника; общий load/writer/loader
и допуск в кэш остаются отдельной задачей.

Продолжение: [собственные таблицы импортов клиента](dis64-owned-imports.ru.md)
и штатное связывание через linkmod.
