# Числовые литералы Point/Rect в локальных вызовах

Обычный локальный Limbo CALL теперь принимает литеральные Draw.Point/Rect, включая отдельные поля int hd …, а также int hd … в scalar int-аргументе. Адрес каждого raw Word32 поля выводится из настоящего layout кадра локальной функции, а не из импортированного ABI. Допускаются FP/MP источники списка строк и 0–32 TAIL; 33 TAIL и aggregate SPAWN остаются закрыты.

Переиспользуется роль 253: bounded TAIL, HEADP в compiler-owned FP root-слот, CVTCW в Word32 подготовленного кадра, немедленная очистка через readonly nil. Module checker до выделений проверяет единственный call site и карту GC его настоящего локального target; все четыре байта назначения должны быть raw. Проверки импортированных вызовов сохранены. Литеральные постоянные и смешанные поля используют обычные проверенные Word32 stores.

utils/tests/native64-local-int-head-args.py: 11 настоящих Limbo-функций и 522 сценария C/JIT. Исполняются реальный OP(cvtcw), локальные Point/Rect/scalar вызовы и Limbo raise. Point передаётся после трёх root-аргументов, со смещением 88 — как в sizewin; проверяется идентичность всех трёх alias-ссылок и их освобождение. Покрыты FP/MP, постоянные и смешанные литералы, повторные вызовы, Rune/nil головы, короткие списки, ошибки UTF-8 cache, первая/вторая ошибка локального callee, рост стека, quantum 1/3/1000, соседние байты и полное освобождение. Контрольный импортированный Audit.check лишь наблюдает аргументы и очищенные root-слоты внутри настоящего локального callee; вычисления остаются в Limbo.

Независимый oracle отвергает 474 повреждения при неизменном classic Dis; 790 вариантов метаданных отвергаются до выделений. Проверены все 35/36 точек отказа создания модуля в C/JIT. Три активных контроля: неверное смещение координаты, пропуск очистки и запись восьми байт вместо четырёх.
