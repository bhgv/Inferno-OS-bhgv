# Lowering целых типизированных функций

Новый `limbo/dis64-typed.c` переносит целое поддерживаемое тело void-функции
из проверенного IR компилятора в инструкции с нативными адресами FP/MP.
Используются размещение по типам и существующие opcode ISA. Это следующий
потребитель после [рецептов аргументов](dis64-typed-source-lowering.ru.md).
[English version](dis64-typed-bodies.md).

## Пример с параметрами формы AWM

```limbo
implement Kernel;
include "sys.m";
include "draw.m";
Kernel: module {
    run: fn(ctxt: ref Draw->Context, argv: list of string, text: string, n: int);
};
answer: int;
result: string;

run(nil: ref Draw->Context, argv: list of string, text: string, n: int)
{
    total := 0;
    while(n > 0) {
        total += n;
        n--;
    }
    answer = total + len text + len argv;
    result = text;
}
```

Посмотреть результат lowering обычным компилятором:

```sh
LIMBO_DIS64_TYPED=1 /host/tools/limbo -I module \
  -o /tmp/kernel.dis kernel.b 2>/tmp/kernel-typed.log
```

Запись `DIS64_TYPED` содержит имя функции, исходный первый PC, точные номера
сериализованных FP/MP-дескрипторов, старые/новые размеры, map8, элементы типов,
адреса аргументов и инструкции `[opcode, mode, source, middle, destination]`.
Аргументы сохраняют вид и старый/новый размер, включая channel/module,
агрегаты по значению и нулевые размеры. Геометрия целого аргумента не выводится
из его первого читаемого скалярного поля.
Параметры примера получают такое размещение:

| Аргумент | Нативное смещение | Нативный размер |
| --- | --- | --- |
| `ctxt` | 64 | 8 |
| `argv` | 72 | 8 |
| `text` | 80 | 8 |
| `n` | 88 | 4 |

Префикс кадра и адрес результата резервируются отдельно. Ссылки перемещаются
через MOVP; числовая операция не может прочитать старую четырёхбайтную ячейку
указателя. Временные big/real могут делить восьмибайтное неразмеченное хранилище
компилятора: текущую интерпретацию определяет opcode. Ссылки со скалярами
таким способом не смешиваются.

## Проверки тела и переходов

Поддержаны прямые переносы byte/Word/big/real/ссылок, числовые преобразования,
арифметика и сравнения Word/big/real, длины String/list/array, прямые и обратные
переходы, void-return. Для opcode проверяются точные размеры и виды ссылок.
Косвенные/служебные адреса, неподдерживаемая инструкция, возвращаемое значение,
handler и полиморфное/variadic-соглашение отклоняют всё тело. Частичный код
в записи отказа не публикуется. Временные планы освобождаются.

Каждый переход обязан указывать на настоящий PC своей функции. Глобальные
старые PC становятся локальными индексами без изменения числа/порядка
инструкций. Сохраняются ограничения middle-операнда. Восьмибайтный immediate
отклоняется, чтобы не читать за пределами Word-ячейки. Вызывающая сторона
обязана предоставить FP/MP с корректной исходной инициализацией. Это lowering
проверенного IR, а не семантическая валидация чужого байткода.

## Исполнение тестов

```sh
python3 utils/tests/dis64-typed-body.py --limbo /host/tools/limbo --awm
python3 utils/tests/native64-arguments.py --formatter --limbo /host/tools/limbo \
  --omission typed-body-branch --omission typed-field-origin
```

Первый тест независимо читает старый Dis: проверяет адреса, opcode/mode,
переходы, точные дескрипторы и сохранение байткода. Порча цели, карты корней,
смещения или дескриптора обнаруживается. C-тест проверяет освобождение после
позднего отказа, классы ссылок, границы заголовка, локальные PC, handler,
wide-immediate и ограничения кода. Три намеренно убранных условия обязаны
провалить соответствующие семантические проверки.

Второй тест исполняет целые полученные тела настоящими VM-обработчиками
переносов, арифметики, преобразований, длин и переходов, с GC между инструкциями.
На комбинацию emu/os и WORD32/WORD32-file приходится 20 случаев: циклы,
ранние return, nil и Unicode/NUL String, непустой список аргументов, отрицательные
счётчики, big/real и владение результатами. Размеченное владеющее хранилище
сохраняет данные FP/MP; освобождение балансирует heap/Type/ссылки. Частный
исполнитель трактует void RET как завершение и восстанавливает регистры caller;
новый производственный путь стека вызовов/планировщика он не устанавливает.

Пройдены AMD64 UBSan, ARM64 UBSan/QEMU и ASan/UBSan компилятора/C-unit.
Открытый runtime-ASan unwind описан в [документе о владельцах аргументов](dis64-native64-arguments.md).
Существующие проверки аргументов и 768 Sys-вызовов сохраняются для каждой
комбинации.

## Реальная граница AWM

В шестнадцати стартовых исходниках целиком переносятся `wmsrv.hide`,
`wmsrv.unhide`, `sh.debug`; остальные 357 тел отклоняются. Старый байткод
не меняется. Это ещё не исполнение этих модулей или AWM. Все 376 прежних
планов хранения отдельно продолжают проходить.

Выходной файл остаётся старым Dis. Ещё нужны генерация общего Dis64-модуля,
инициализированный MP, импорты/экспорты, вызовы и возвращаемые значения,
операции с содержимым heap, таблицы, исключения и обычный variadic-startup.
Общий допуск модулей, новые wire-ID, исполнение тела JIT и готовность Android
GUI APK этим этапом не заявляются.
