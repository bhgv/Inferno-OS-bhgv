# Native64: array of ref Draw.Image

Добавлено выделение массивов канонических ссылок Draw.Image в FP/MP. Компилятор проверяет исходный descriptor элемента: classic ref, 4 байта, карта 0x80. Роль 254 несёт отдельный token 2, который нельзя принять за byte-array при удалении роли. Owning module builder устанавливает приватный Type: 8 байт, один mapped root. Он сосуществует с отдельным byte Type и остальными приватными типами модуля. Используется настоящий OP(newaz), включая H-инициализацию элементов, проверки длины и retain-счётчиков.

Чтение/запись — точная пара роли 255: classic INDW преобразуется в native INDL со stride 8, за которым немедленно идёт MOVP. Адрес элемента заимствован в зарезервированном FP48, не включён в GC-карту; сам Array остаётся в mapped root-слоте. Consumer допускает только прямой FP/MP слот. Вход на consumer через обычный branch или case/goto-table запрещён до выделений; оставлена также проверка при materialization. Пары внутри подготовки CALL остаются закрыты, как и interleaved индексы с двумя одновременно живыми адресами. Alias проверяется через явную временную ссылку.

utils/tests/native64-image-arrays.py проверяет неизменность classic Dis и element descriptor, независимый oracle (240 повреждений), 360 отказов метаданных до выделений и все 28/29 точек отказа создания модуля C/JIT. Runtime: 3168 сценариев с настоящими heaparray/initarray/freearray, newaz, indl и movp: пустые массивы, FP/MP чтение и запись, nil, alias, замена Image, повторное выделение, сосуществование с byte-массивами, отрицательные и предельные Word32 индексы/длины, ошибки выделения и переполнение Type retain на первом/втором newaz, Limbo raise, quantum 1/3/1000, рост стека, соседние элементы и полное освобождение. Три активных контроля: пропуск root-бита Type, stride 4 вместо 8 и пропуск раннего запрета branch на consumer.

В настоящем AWM sizewin проходит PC901 (array[4] of ref Image) и останавливается на PC902 multi-callee при showborders. showborders останавливается на PC1095 image-array-index: элемент передаётся прямо в pending frame локального вызова, а обычная непосредственная пара index/movp этого не допускает. handlerequest пока на PC618 multi-callee, awm.init на PC303. dragwin принята целиком.
