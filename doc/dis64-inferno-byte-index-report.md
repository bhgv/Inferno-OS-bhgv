# INFERNO-0194 — selected byte-array indexing from Limbo

2026-11-15. Base07759b7f /0193. Ordinary selected Command libraries and importing
clients now compile and execute byte-array element reads and writes, including
local byte values, int casts, constant/local indexes, loops, aliases, slices,
UTF-8 and embedded NUL. This is source admission above0193's native-pointer C/JIT
correction; it does not replace the VM or admit general managed AWM programs.

## Lowering and ownership

Limbo's legacy array-address temporary remains an int in the old IR. The trusted
producer recognizes only an adjacent INDB followed by MOVB/CVTBW reading the byte,
or MOVB/CVTWB writing it. It redirects both to the already reserved first tail
cell at native frame size minus16. This unmapped cell holds a full native pointer;
the separate scalar MCALL result remains at frame size minus8. Frame sizes, maps,
Decl layouts, public kinds, signatures, opcodes and Dis64 sections are unchanged.

The independent verifier treats this pair as one CFG node, checks its exact
scratch identity, operand classes and initialization, and refuses incoming edges
into the consumer. Runtime scheduling still executes two instructions. Its mapped
array owner stays live between them; there is no intervening instruction that
could overwrite the root. Slices retain their backing owner normally. Standalone
indirect byte operations, arbitrary scratch locations, nonzero displacements,
root/result overlaps, unmatched INDB and general INDW/INDX remain refused.

Normal Byte locals and byte/int conversion operations carry a distinct internal
proof class of width1. Compiler-generated byte constants formerly stored in MP
are folded to immediate operands after exact declaration/value checks. Their
legacy layout leaves are accounted for, but no byte DATA is emitted. Mutable
MP stores and arbitrary global data remain outside this profile.

The native instruction constructor now distinguishes INDB's immediate numeric
index in the destination field from a branch destination. Previously it stored
`program + index` there; the interpreter then read low address bits as an index.
Only admitted INDB uses this numeric destination rule; branch materialization is
unchanged. The complete interpreter and ARM64 JIT execute the resulting files.

 roots with real GC and caller/provider interpreter/JIT combinations.28 pairs are
 new byte-index programs, including seven negative/nil/end write/read failures.
* 684 main roots in each rebuilt complete x64 and ARM64 console, plus missing-file,
 hash, default-policy, entryless-module and tutorial controls. No builtin-free
 substitute is used for this complete namespace/heap/scheduler execution.
* 113 independent valid/malformed raw images on each architecture; host proof also
 runs ASan/UBSan. Scratch-identity and consumer-boundary omission controls fail
 semantically, without executing the malformed image.
* An independent GC observer verifies the exact published pointer equals
 `array->data + index` when suspended immediately after INDB. Positive indexed
 runs require actual observations. A targeted owner-mark omission only in that
 pause fails before resuming on both architectures. Separate backing-array and
 byte-owner omissions detect retention failures as well.
* 33 scalar-library client pairs include five new index-then-MCALL cases, checking
 the borrowed-address cell and native scalar result binding coexist with GC.
* 354 deterministic selected source files;62 prior importing clients and all classic
 outputs compare byte-for-byte to the previous compiler. Prior149 Command pairs
 retain their298 selected images; only index-prefixed source cases need new
 admission. RU/EN tutorial blocks remain identical and compile in both modes.

Reproduce using dis64-command.py, dis64-command-boot.py,
dis64-client-index-proof.py (also `--control scratch` / `boundary`),
dis64-client-literal-scalar.py and dis64-command-producer.py with

`dis64-command.py --limbo PATH --case index-read --gc-control index-owner`.
The existing native64 ARM64 runner/cross-compiler options apply.
