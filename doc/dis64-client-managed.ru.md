# Строки и списки внутри файлового клиента Dis64

[English version](dis64-client-managed.md).

Файловый клиент теперь получает локальные String и `list of string` с картами GC.
Загрузчик проверяет классы ссылок, переносит карты в runtime Type и использует
существующие обработчики ссылок/списков и JIT. Сигнатуры вызовов библиотеки остаются
скалярными, вход клиента — void без аргументов. Это подготовка управляемого heap и
кадра к обычному `Shell.init(context, argv)`, а не поддержка этой сигнатуры.

## Полный пример обхода списка

`library.m`:

```limbo
Library: module {
    PATH: con "/demo/library.dis64";
    inc: fn(n: int): int;
};
```

`library.b`:

```limbo
implement Library;
include "library.m";
inc(n: int): int { return n+1; }
```

`client.b`:

```limbo
implement Client;
include "library.m";
Client: module { init: fn(); };
init() {
    m := load Library Library->PATH;
    if(m == nil)
        return;
    s := Library->PATH;
    words := s::s::nil;
    n := 0;
    while(words != nil) {
        part := hd words;
        n += len part;
        words = tl words;
    }
    expected := 2*len s+1;
    last := m->inc(n);
    if(last != expected) {
        zero := 0;
        bad := 1/zero;
    }
    keeps := s;
    keepwords := words;
}
```

Создайте `/demo` внутри корня эмулятора:

```sh
limbo -64b -I . -o /path/to/root/demo/library.dis64 library.b
limbo -64c -I . -o /path/to/root/demo/client.dis64 client.b
emu -r /path/to/root -X dis64-calls -c 1 -d /demo/client.dis64
```

`-c 0` выбирает интерпретатор. Исправный пример завершается без вывода. Отсутствие
библиотеки обрабатывает обычный nil-guard, неверный ответ ловится проверкой в Limbo.
Ожидаемый результат вычисляется из настоящей длины пути, поэтому перенос примера
не зависит от числовой константы с длиной имени файла.

## Значения и время жизни

Этот профиль допускает String с уже созданным именем файла либо nil и плоские
списки этих строк. Дополнительные строковые DATA-константы, конкатенация,
списковые импорты/экспорты, вложенные списки, массивы и графы ADT пока не входят
в writer. Сохраняются один путь/таблица импорта и ограничения кода/кадра; лимит
64 проверяемых ячеек теперь общий для скаляров и mapped roots.

| Операция | Поведение |
| --- | --- |
| `alias := s`, `alias := words` | Удерживает тот же управляемый объект |
| `s = nil`, `words = nil` | Освобождает прежнее владение |
| `len s`, `len words` | Длина nil равна нулю |
| `s::words` | Создаёт узел со ссылочной головой и сохраняет голову/хвост |
| `hd words` | Возвращает удержанную String-голову |
| `tl words` | Возвращает удержанный хвост списка |
| `words == nil`, `words != nil` | Сравнивает ссылку по полной ширине |

Nil-проверка списка не обрезает указатель до Word32. `hd nil` и `tl nil` вызывают
существующую ошибку VM `dereference of nil` с нормальным освобождением ресурсов.
Равенство/конкатенация строк и произвольные сравнения ссылок здесь не добавлены.
Runtime сохраняет собственные Type и существующий Tptr для элементов списка;
структуры C в файл не сериализуются.

Mapped locals получают H через обычную инициализацию кадра. Только эти значения
считаются изначально определёнными; скаляр по-прежнему обязан получить запись на
всех входящих путях CFG. Перед проверкой операций распространяется равенство
классов через MOVP. Неуточнённый root — исходный nil или его nil-алиасы, пока
операция не задаст класс. Он не разрешает произвольные указатели/дескрипторы.
Классы String и списка нельзя смешивать. Набор производителей замкнут: имя файла,
nil, MOVP, CONSP, HEADP, TAIL.

Карта не может помечать служебный префикс кадра или зарезервированную скалярную
ячейку результата. Числовые операции не пересекают roots, ссылочные — unmapped
ячейки. Для mapped caller используется существующая typed-привязка адреса
результата: она отдельно проверяет unmapped ячейку и подготовленный кадр callee.
Адрес остаётся внутренними native-данными конструктора; wire LEA и скалярные
сигнатуры прежние. Старые scalar-only клиенты сохраняют binder и точные байты.

## Проверки GC и отказов

```sh
python3 utils/tests/dis64-scalar-client.py --managed --gc --limbo /path/to/limbo
python3 utils/tests/dis64-scalar-client-managed-proof.py --limbo /path/to/limbo
python3 utils/tests/dis64-scalar-client-managed-producer.py \
  --limbo /path/to/limbo --baseline /path/to/prior/limbo
python3 utils/tests/dis64-scalar-client-boot.py --managed \
  --limbo /path/to/limbo --root /path/to/root --emu /path/to/emu
```

Настоящий collector проходит три полные цветовые эпохи между нетерминальными
квантами VM. Арена поддерживает sweep. Независимый наблюдатель запоминает достижимый
граф кадра/списков и проверяет его сохранность до следующей инструкции. Отключение
маркировки кадра или обхода списка должно потерять наблюдаемый объект и дать
семантический exit10. Авария или сообщение sanitizer не засчитываются. Ссылки,
дескрипторы, модули, стеки и все ячейки арены должны освобождаться. Namespace/I/O
в этой матрице остаются стендовыми; полный emu исполняется отдельной проверкой.

Для другого target используются `CC`, `NATIVE64_ARCH`, `NATIVE64_RUNNER`; boot
принимает `--runner`. Проверка native-порта включает GC-матрицу и omission controls.
Host ASan/UBSan покрывает независимую проверку файлов и создание/освобождение
объектов; новые гарантии whole-VM ASan или конкурентного GC не заявляются.
Linux/QEMU не подтверждает запуск Android GUI/Bionic или APK на устройстве.
