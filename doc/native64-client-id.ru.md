# Native64: Client.id → String и локальный String-аргумент

Настоящий awm.init проходит `controlevent("newclient "+string c.id)`
на PC243–247 и доходит до PC257 load-nil-roles. setfocus, controlevent
и reshaped принимаются целиком. Это проверка компилятором checked-профиля;
графический AWM и Android UI пока не запущены.

Добавлены два узких пути checked LOAD:

- Role237: ICVTWC из канонического Wmsrv.Client.id (classic36/native72)
  в прямой FP String root. Читаются ровно четыре байта id, ссылка на Client
  и результат String занимают по восемь байт. Полный layout Client
  проверяется существующим proof, а не одним совпавшим offset.
- В подготовленном локальном IFRAME: role237, один IADDC в String-аргумент
  дочернего кадра, затем role238 — clear временного String перед ICALL.
  Допускаются префикс и суффикс; один из входов IADDC обязан быть результатом
  конвертации. Целевая функция имеет единственный String-аргумент и void
  result. SPAWN, импортируемая функция, несколько параметров, result binding
  и цепочки дополнительных промежуточных concat этим путём не открываются.

Сохраняются настоящие cvtwc/addc и существующий JIT. Другие поля Client,
чужие ADT, прямой MP destination и inherited result для конвертации не
добавляются. Можно сохранить результат в обычный локальный String, затем
использовать уже существующие операции передачи или присваивания.

До выделения модуля проверяются opcode/modes, offset72, полные spans,
карты обоих roots и структурная связь с локальным вызовом. Для составного
аргумента дополнительно проверяются caller temporary, root64 дочернего
кадра, единственный callsite, точные позиции convert/concat/clear,
readonly nil и его map, а также отсутствие orphan clear. Конвертация может
быть самостоятельной; clear238 может существовать только в этой локальной
последовательности. GC map не доказывает nominal тип heap-объекта сама:
semantic premise о Client.id поступает из проверенного compiler IR.
Загрузка произвольного native файла не разрешается.

Новый native64-client-id.py проверяет:

- 756 C/JIT случаев: FP/MP owner, самостоятельная конвертация и локальный
  prefix/suffix CALL, три quantum, 0/1/-1/int32 min/max/старший бит и nil.
  Используются настоящие cvtwc, addc и lib9 integer formatter.
- Ошибки выделения в обработчиках конвертации и конкатенации со штатным
  exHeap, nil-owner unwind, сохранность старого глобального результата,
  всего payload Client и caller guards, полное освобождение String,
  module links и кадров.
- При интерпретируемом локальном CALL приёмник через parent Frame проверяет,
  что temporary вызывающей функции уже H до сохранения аргумента в out.
  Для JIT проверяется результат и полное освобождение; callback-наблюдение
  не требуется, если native MOVP обходит optab.
- 60 повреждений независимо обнаруживает classic Dis oracle;
  исходные bytes и канонические сигнатуры сверяются отдельно.
- 108 повреждений metadata отвергаются до выделений: opcode, modes,
  offset, spans, карты, обязательный clear, readonly nil и target root.
  Конструктор даёт полный rollback в 25/26 точках C/JIT.
- Два активных контроля должны давать смысловой отказ: подмена id72 на
  flags32 и очистка другого root вместо temporary. Во втором контроле
  сохранён допустимый MOVP, поэтому проверяется выполнение, а не отказ
  JIT-компиляции. Sanitizer crash не засчитывается.

Gate подключён к native64-port.py и обоим путям CI. Обычные Dis bytes и
32-битный код сохранены. Локальный прогон — amd64; выполнение arm64/riscv64
CI и Android UI этим результатом не заявляется.

Локально прошли UBSan и ASan+UBSan (`detect_leaks=0`, с явными счётчиками
владения), включая оба активных контроля. Регрессии local concat624 и
Client.cursor arguments192 прошли со своими контрольными мутациями.
Отдельная чистая amd64 сборка прошла console/pair boot и 324 процесса
настоящего Arg/emuinit.
