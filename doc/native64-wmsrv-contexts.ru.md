# Контекст и обмен изображениями Wmsrv в native64

Полный неизменённый `appl/lib/wmsrv.b` принимает 31/34 checked IR тела
вместо 27/34. В исполняемый кластер добавлены четыре исходные функции:
`newwmcontext`, `senderror`, `Client.setimage`, `Client.setorigin`.

Закрытая раскладка Draw.Wmcontext содержит семь GC-ссылок: 28 классических
байт превращаются в 56 native64, карта fe. Создание каналов в полях объекта
сохраняет настоящий Word32 mover клавиатуры и pointer mover остальных
каналов. Полная копия Wmcontext использует IMOVMP с приватным native Type:
копия владеет теми же каналами и переживает освобождение оригинала.
Draw.Point выделяется как два raw Word32, 8 байт без GC-корней.

Обычные send/recv теперь переносят группы из двух или трёх управляемых
ссылок, включая nil. Проверяются все корни payload, корень канала и его
владелец; поле Client.images ограничено канонической раскладкой Client и
native offset 64. Примитивный int recv может писать прямо в Word32-результат
функции. Для ALT и IMOVMP используются те же доказанные группы корней.

Геометрия: Image.r копируется в Window.r как четыре Word32, с разными
смещениями в двух heap owners. Ref Point получает два Word32 из доказанного
raw span. Составной Rect записывается в Window только после проверки всех
четырёх исходных raw leaves, непрерывности и полной раскладки Window.
Это не копирование C long и не общий непроверенный доступ к ADT.

Private annotations: 90 — полная mapped-копия Wmcontext, 107 — root-group
transfer, 108 — создание примитивного канала в Wmcontext, 109 — int recv в
результат, 110 — Image.r→Window.r. Существующий протокол 215 дополнен raw
Point по offset 0. Байты classic Dis сохраняются побайтово; 32-битный путь
не меняется.

## Исполнение

`utils/tests/native64-wmsrv-windows.py` теперь сохраняет 18 исходных тел без
редактирования. Fixture содержит 36 принятых тел: эти 18, 17 тестовых
вспомогательных функций и один неисполняемый init, заменённый на raise.
Все 35 остальных тел действительно исполняются. Полный оригинал отдельно
компилируется и сверяется независимым декодером classic Dis.

1212 публичных вызовов C/JIT проходят при квантах 1/3/1000 и расширении
стека. Для новых операций используется настоящий планировщик и отдельный
Limbo-процесс-получатель, включая блокирующий ответ по созданному внутри
setimage/setorigin каналу. Проверяются:

- свежие каналы и nil-поля Wmcontext, копирование и независимое освобождение;
- nil/пустые/Unicode ответы senderror, идентичность String и nil-контекст;
- создание Window, смена Image с сохранением Window, снимок Rect;
- идентичность Point/Image в сообщении, возврат ответа Word32;
- успешный origin с исходными C Rect_size/Point_add и отказ без изменения Rect;
- удаление первого и последующего Window без лишнего обмена;
- освобождение каналов, payload, процессов, сред, модулей и объектов.

492 повреждения source report обнаруживает независимый oracle. Runtime
отклоняет 480 повреждений метаданных и 41 повреждение GC-карт до выделения
памяти. Проверяется rollback всех 98/99 точек отказа C/JIT конструктора.
Активные контроли портят карту Client, результат Rect_contains и карту
Wmcontext. Прежние тесты реестра, поиска окон, изображений и z-order входят
в ту же матрицу. Полный прогон с тремя активными контролями проходит
ASan/UBSan на amd64. Регрессии ALT replies/requests, AWM call cluster, Bufio
и очередей Wmsrv, чистая сборка и pair/emuinit boot проходят.

```sh
python3 utils/tests/native64-wmsrv-windows.py --limbo /path/to/limbo
```

Остаются три тела полного Wmsrv: init, wm и childminder. Новый frontier:
wm — reference-class PC94, childminder — alt-field-channel PC249; init
останавливается на вызове wm. Тест не исполняет серверный цикл целиком и не
подтверждает admission полного файлового графа, окно AWM или Android GUI.
