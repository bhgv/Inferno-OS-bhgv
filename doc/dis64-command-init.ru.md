# Обычный Command.init через load в Dis64

Выбранный режим `-64b` / `-64c` компилирует и исполняет настоящее объявление
`Command.init(ctxt: ref Draw->Context, argv: list of string)` из `module/sh.m`.
`load` связывает модуль; затем вызывающий код явно делает `m->init`.
У библиотеки нет точки входа процесса, обычный RET возвращает управление клиенту.
Именно sh вызывает init после загрузки; загрузчик автоматически его не запускает.

Сохраните три блока как `command.m`, `library.b` и `client.b`. Обёртка включает
существующие объявления интерфейсов, а не описывает новый ABI вручную.

```limbo
include "sys.m";
include "draw.m";
include "sh.m";
```

```limbo
implement Command;
include "command.m";
init(ctxt: ref Draw->Context, argv: list of string)
{
    if(ctxt == nil || ctxt.display != nil) return;
    saved := ctxt;
    display := ctxt.display;
    screen := ctxt.screen;
    wm := ctxt.wm;
    ctxt.display = nil;
    ctxt.screen = nil;
    ctxt.wm = nil;
    ctxt.display = display;
    ctxt.screen = screen;
    ctxt.wm = wm;
    greeting := "Привет";
    if(len greeting != 6 || greeting[0] != 1055){ z := 0; bad := 1/z; }
    original := greeting;
    greeting += "!";
    greeting[0] = 1057;
    middle := greeting[1:6];
    if(original != "Привет" || greeting != "Сривет!" || middle != "ривет"){
        z := 0; bad := 1/z;
    }
    total := 0;
    while(argv != nil){
        part := hd argv;
        total += len part;
        argv = tl argv;
    }
    if(total != 11){ z := 0; bad := 1/z; }
    keep := saved;
}
```

```limbo
implement Client;
include "command.m";
Client: module { init: fn(); };
init()
{
    m := load Command "library.dis64";
    if(m == nil) return;
    number := 42;
    text := string number;
    bytes := array of byte text;
    decoded := string bytes;
    capacity := 4;
    buffer := array[capacity] of byte;
    view := buffer[1:3];
    buffer = nil;
    view[0] = byte 65;
    value := int view[0];
    if(value != 65){ z := 0; bad := 1/z; }
    if(len view != 2){ z := 0; bad := 1/z; }
    parsed := int decoded;
    if(parsed != number || len bytes != 2){ z := 0; bad := 1/z; }
    argv := "wm" :: "Привет" :: "a\0z" :: nil;
    ctxt := ref Draw->Context(nil, nil, nil);
    m->init(ctxt, argv);
    if(len argv != 3){ z := 0; bad := 1/z; }
    m->init(nil, argv);
    keep := ctxt;
}
```

Сборка новым компилятором Limbo с каталогом module этого репозитория:

```sh
limbo -64b -I module -I . -o library.dis64 library.b
limbo -64c -I module -I . -o client.dis64 client.b
limbo -H -M Command -I module command.m > command.h
```

Положите оба образа в корень эмулируемого пространства имён и запустите консоль:

```sh
emu -r /path/to/root -c 0 -X dis64-calls -d /client.dis64
emu -r /path/to/root -c 1 -X dis64-calls -d /client.dis64
```

Ожидаются пустая строка завершения Client и нормальное освобождение корня.
Без явного opt-in режим отказывает. Запуск библиотеки через `-d /library.dis64`
также запрещён: это модуль без точки входа процесса. Неудачный load возвращает
nil и не исполняет init. Специального автоматического вызова init в загрузчике нет.

## Типы, хэши и кадры

`Sys` или `Command` в load — описатель интерфейса. Выражение пути задаёт файл
модуля либо внутреннее имя вроде `$Sys`. Limbo переводит load в Dis, а
интерпретатор работает с Dis. Здесь добавлено файловое связывание Command.

Генерация `limbo -H -M Command` и выбранный Dis64 writer используют существующий
`sign(fn)` по `.m`; для текущих объявлений хэш равен `4244b354`. Загрузчик проверяет
полные байты сигнатуры, имя модуля и символа, затем передаёт **хэш потребителя**
обычному `linkmod`. Хэш проверяет согласованность, а не подлинность.
Обычное связывание клонирует MP. Полностью построенный исходный модуль включается
в список modules до снятия временного MP pin; обычный unload удаляет его.
Отказы выделения памяти освобождают промежуточных владельцев.

| Значение | Native-размещение | Роль для GC |
| --- | --- | --- |
| ctxt | FP+64 вызываемой функции | ссылка Context |
| argv | FP+72 вызываемой функции | список строк |
| префикс параметров | всего 80 байт | карта `00 c0` |
| пустой Draw.Context | 24 байта | три pointer-поля, исходно nil |

MFRAME/MOVP/MOVP/MCALL готовят обычный кадр и копируют аргументы. Изменение
переменной argv в библиотеке не меняет переменную клиента; сами ячейки списка
и строки остаются общими управляемыми объектами. Настоящий GC видит оба кадра,
включая локальные cons-ячейки библиотеки. Проверены C dispatch и JIT.

`ctxt := ref Draw->Context(nil, nil, nil);` создаёт запись с nil в display/screen/wm.
Теперь в выбранном профиле допускаются три pointer-поля Context: native-смещения
0/8/16 вместо classic0/4/8. Сначала прочитайте поле в типизированную локальную
переменную; затем ссылку можно копировать, очищать, восстанавливать и сравнивать
с nil. У Display, Screen и wm разные внутренние роли: их нельзя использовать
как Context, String или ListString. Настоящий GC обходит поля и их локальные
алиасы. Запись использует прежний MOVP с его reference counting и barrier.

Это перенос ссылок, а не создание GUI-ресурсов. Вложенные разыменования,
выделение Display/Screen, операции каналов и indirect-to-indirect копирование
пока отклоняются. Прямые условия `ctxt.display == nil` / `!= nil` и сравнения
идентичности совместимых ссылок Context/list/field теперь допускаются. Сравнения
используют все 64 бита. Равенство и упорядоченные сравнения String теперь работают по содержимому
со знаковым порядком Rune32; nil и пустое содержимое равны. Индексация строки
возвращает Rune в int, сохраняя Unicode и внутренний NUL.
Короткое замыкание условий позволяет не разыменовывать nil-контекст.

`ref Draw->Context(nil,nil,nil)` теперь работает в объявлениях locals,
присваиваниях, циклах и конструкторах библиотеки. Выбранный компилятор сохраняет
тип временных Context вместо переиспользования ячейки String/List. Перед вызовом
init сохраните конструктор в local: конструктор внутри подготовки вызова пока
отклоняется. Ненулевая ссылка не создаёт дисплей или окна.
Точные проверки: [INFERNO-0189](dis64-inferno-client-literals-report.md).

## Точная граница частного эксперимента

Частная сигнатура — четыре big-endian слова: `face0186`, существующий Limbo-хэш,
число аргументов `2`, результат void `0`. Это **новая частная пробная схема**,
а не назначение общего managed ABI. Новых публичных opcode, section или type-kind
ID нет; прежние scalar v1 сигнатуры побайтно сохранены. Совместимость произвольных
managed-сигнатур между реализациями этим не устанавливается.

У библиотеки один экспорт Command.init PC0/frame0, нет импортов и вызовов helpers;
тело ограничено независимой проверкой, используются прежний частный префикс MP 24 байта и корни литералов с картой GC.
Точка входа клиента остаётся void без аргументов. Допускается один интерфейс/путь.
Допускается до32 дополнительных readonly String-корней на образ:
до255 Rune в одном и1024 суммарно. Общие DATA-инициализаторы, другие экспорты, поля произвольных ADT,
произвольные ADT и массивы остаются за границей. Нужный MOVP из MP в подготовленный
кадр разрешён локальным reader клиента; общий scalar reader не расширен.

Проверки в utils/tests: `dis64-command.py` — исходники/GC,
`dis64-command-boot.py` — полная консоль, `dis64-command-proof.py` — повреждённые
образы без исполнения, `dis64-command-producer.py` — совместимость.
Все принимают `--limbo`. Контроль пропуска маркировки кадра библиотеки должен
обнаружить потерю наблюдаемого объекта до возобновления исполнения.
Проверки Linux x64/ARM64 QEMU не означают готовый Android/Bionic GUI APK.

Раскладка строк повторяет прежний частный managed-file trial: дополнительные
Rune-записи следуют за именами bindings, их владельцы находятся в MP24+8*i.
Размер и карта MP покрывают каждый корень. При расширении MP отдельный
дескриптор2 описывает Context24/E0; INEW использует его, а не увеличенный MP1.
Без литералов сохраняются прежние два дескриптора и байты старых образов.
Это частная opt-in раскладка, а не общий публичный ABI managed-инициализаторов.

Исходное `""` сохраняет classic nil-представление в MP8. Сериализованная запись
с нулём Rune создаёт отдельного ненулевого владельца пустой String; проверки
конструктора различают ссылки, хотя сравнение содержимого приравнивает nil
и пустую строку. ASCII может храниться в байтах, прочие строки — в Rune.
C-расширения должны учитывать длину и представление String: strlen обрежет NUL.
Конкатенация, запись символа в локальную строку и срезы теперь используют прежние
ADDC, INSC и SLICEC. Нужны локальные корни с картой GC; общие литералы и алиасы
сохраняются копированием при изменении. Индекс, равный длине, добавляет символ;
больший или отрицательный индекс вызывает ошибку границ. Срезы считают символы,
включая Unicode и NUL. Общие payload-конструкторы пока не допускаются.


Теперь допускаются прежние преобразования String в int/big/real и обратно.
`array of byte s` кодирует UTF-8, `string bytes` декодирует его. Длины различаются:
у String считаются символы, у массива — байты; NUL сохраняется. Массивы имеют
обычное владение runtime и корни с картой GC. Это не общий DATA-инициализатор:
здесь разрешены преобразование байтового массива, длина, копии, идентичность,
обнулённые конструкторы, срезы и индексация байтов; другие типы элементов ещё не допускаются.


Для байтовых массивов теперь доступны `array[n] of byte` и срезы вида
`buffer[1:3]`. Этот профиль обнуляет новые буферы. Срез удерживает исходный массив
после присваивания nil его прежней переменной; границы и длина считаются в байтах.
Отдельный проверенный дескриптор байта появляется только при конструкторах и
не подменяет дескриптор Context. Общие инициализаторы
массивов и другие типы элементов пока не допускаются.

Индексация байтов теперь допускает `n := int buffer[i]`, `b := buffer[i]` и
`buffer[i] = byte n`; индекс — локальная int-переменная или константа.
Чтение в int беззнаковое. Отрицательный индекс, nil и индекс за концом вызывают
прежнюю ошибку границ массива. Компилятор переносит соседнюю пару вычисления
адреса и обращения к байту в зарезервированную ячейку native-указателя.
Массив-владелец остаётся корнем GC при паузах планировщика. Вход переходом во
вторую инструкцию запрещён. Общие инициализаторы, другие типы элементов и
составная арифметика байтов пока не допускаются.
