# Типизированные переносы из FP/MP в нативные аргументы

Расчёт размещения по типам теперь используется частным генератором аргументов
variadic-функций Sys. `native64callstores` получает смещения и карты FP/MP через
`dis64layoutstorage`, а каждое чтение проверяет через `dis64layoutaddress`.
Старое расширение ячеек только по битам дескриптора убрано.
[English version](dis64-typed-source-lowering.md).

## Вложенные поля и локальная копия

Файл `typedfield.m`:

```limbo
Probe: module {
    Inner: adt { count: int; text: string; wide: big; };
    Outer: adt { lead: byte; inner: Inner; fraction: real; };
    init: fn();
};
```

Файл `typedfield.b`:

```limbo
implement Probe;
include "sys.m";
include "typedfield.m";
original: Outer = Outer(byte 123, Inner(-17, "Grüße\0世界", big -17), -1.25);
init()
{
    sys := load Sys Sys->PATH;
    seed := original;
    sys->sprint("%d|%s|%bd|%g",
        seed.inner.count, seed.inner.text, seed.inner.wide, seed.fraction);
}
```

Получение частных рецептов аргументов обычным компилятором:

```sh
/host/tools/limbo -I module -I . -Dq -o /tmp/typedfield.dis typedfield.b \
  2>/tmp/typedfield-calls.log
```

Результат остаётся старым Dis. Рецепт выполняется нативными тестами ниже;
допуска такого caller через `-64l` пока нет. Старый файл этим не становится
исполняемым на LP64. Новый общий wire-профиль не назначается.

| Поле | Старое относительное смещение | Новое относительное смещение | Новый размер |
| --- | --- | --- | --- |
| `lead` | 0 | 0 | 1 |
| `inner.count` | 8 | 8 | 4 |
| `inner.text` | 12 | 16 | 8 |
| `inner.wide` | 16 | 24 | 8 |
| `fraction` | 24 | 32 | 8 |

Старый размер — 32 байта, нативный C требует 40. Word читается как четыре
байта, затем CVTWL расширяет его со знаком до восьмибайтного variadic-слота.
Big/real сохраняют восемь байт. String переносится через MOVP с сохранением
владельцев и отметкой GC.

## Генератор и границы исполнения

Вложенные инициализаторы MP разбираются по настоящим объявлениям полей и узлам
AST. Сохраняются длины UTF-8, внутренний NUL, signed64 и канонические биты real.
Перехода по ссылке ради выдуманного постоянного содержимого heap нет.
Неизвестные и динамические входы остаются явными.

Прямой MOVMP из MP в FP может определить поле последующего аргумента.
Проверяются Type копии, размер дескриптора, точный вид/размер поля и координаты,
а также существующие ограничения на ветвления, исключения и вызовы.
`cell.aggregate` сохраняет реальные opcode, дескриптор и старые базы копии.
Несколько полей могут иметь один PC; независимый тест требует одну и ту же
исходную инструкцию. Policy `typed-word4-ref8` содержит полные элементы и map8.
Padding, часть указателя, скаляр через границу поля и заимствованный адрес
не допускаются как обычные аргументы. При отказе частичный план освобождается.

Рецепт проецирует поля, используемые этим путём аргументов. Общий managed-lowering
ещё должен сохранять алиасы, порядок и всех владельцев целой копии, включая
неиспользованные поля. Общие цепочки копий, косвенное чтение heap, арифметика
внутри подготовки аргументов и общий граф управления пока вне генератора.
Текущее значение берётся при каждом чтении, без кэширования первого результата.

## Проверка

```sh
python3 utils/tests/native64-callsites.py --limbo /host/tools/limbo
python3 utils/tests/dis64-layout.py --limbo /host/tools/limbo
python3 utils/tests/native64-arguments.py --formatter --limbo /host/tools/limbo
```

Последний тест охватывает emu/os и WORD32/WORD32-file. На каждую комбинацию
приходятся 768 существующих настоящих FRAME/MFRAME/MCALL/GC-проверок четырёх
Sys-gateway и новые переносы глобальных, локальных и скопированных вложенных
полей обработчиками VM. Заголовок из `.m` даёт C-проверки sizeof/offsetof.
Владеющая размеченная память сохраняет MP, FP, промежуточные и конечные слоты
при GC между шагами. Проверяются точный Unicode/NUL, числовые биты и ссылки.

`--omission NAME` выбирает нарушения formatter, сохраняя все положительные
случаи и проверки владельцев. Для изменённого пути: `typed-field-origin`,
`source-map`, `store-reference`, `fp-current-mp`. Они обязаны провалить
семантические проверки. Порча координат/дескриптора/проекции копии обнаруживается
чтением старого Dis. Пройдены ASan/UBSan компилятора, AMD64 UBSan обработчиков
и ARM64 UBSan/QEMU. Открытый runtime-ASan unwind описан в
[документе о владельцах аргументов](dis64-native64-arguments.md).

Все 376 планов AWM по-прежнему проходят, обычный байткод не меняется. На пути
к Android GUI ещё нужны генерация и допуск общих managed-образов, исполнение
обычных variadic-хвостов, дескрипторы содержимого, генераторы таблиц и исключения.
