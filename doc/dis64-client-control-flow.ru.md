# Ветки, циклы и проверка module на nil

[English version](dis64-client-control-flow.md).

Файловый клиент теперь поддерживает управление потоком вокруг loads и вызовов.
Граница остаётся прежней: один init без аргументов и результата, один путь/таблица
библиотеки, скалярные сигнатуры. Аргументы обычного AWM init и общие managed-графы
ещё не допускаются. Интерфейс, исходник библиотеки и команды сборки приведены в
[туториале файлового клиента](dis64-scalar-clients.ru.md).

## Отсутствующий модуль и вызов в цикле

Для прежнего Library.inc:

```limbo
implement Client;
include "library.m";
Client: module { init: fn(); };
init() {
    m := load Library Library->PATH;
    if(m == nil)
        return;
    n := 0;
    while(n < 5) {
        n = m->inc(n);
    }
    if(n != 5) {
        zero := 0;
        bad := 1/zero;
    }
}
```

```sh
limbo -64b -I . -o library.dis64 library.b
limbo -64c -I . -o client.dis64 client.b
emu -r /path/to/inferno-root -X dis64-calls -c 1 -d /demo/client.dis64
```

Без библиотеки программа штатно завершится после nil-проверки. Если inc прибавляет
единицу, цикл заканчивается на5. Типизированная, но неверно считающая библиотека
попадает в проверку результата самой команды. Вывод Sys и автоматический init
библиотеки не добавлялись. Политика подписи и полное сопоставление сигнатур остаются
обязательными до получения связанного экземпляра.

Поддержаны сравнения Word/Big/Real, if/else, обратные переходы, циклы,
break/continue и ранние return. Загрузку можно повторять внутри цикла. Module
local можно сравнивать с nil на равенство/неравенство в обоих порядках операндов.
Другие ссылочные сравнения отклоняются. Прежние пределы128 исходных/256 wire
инструкций,4096 байт кадра и64 скалярных span/импорта/аргумента сохранены.

## Ширина ссылок

Классический IR Limbo сравнивает module ссылку Word-инструкцией. В выбранном
клиентском режиме компилятор использует проверенные типы объявлений и переводит
module/nil сравнение в существующие восьмибайтовые BEQL/BNEL. Операнды приводятся
к MP0 с module root и MP8 с постоянным H. Новых opcode, signature kind, секций,
сериализованных native-указателей или layout нет.

Raw-проверка разрешает ссылочное чтение только для этой точной формы Long equality.
Word-сравнение тех же managed-ячеек и чтение других MP-ячеек отклоняется.
Обычные Big/Real сравнения сохраняют разные числовые виды. Тесты включают Big со
значащими битами выше32 и отрицательные Real, для которых целочисленный порядок
битов выбрал бы неправильную ветку.

## Проверка CFG

После вставки копирования результатов из native-хвоста компилятор пересчитывает
каждую цель перехода. MFRAME, аргументы, привязка результата, MCALL и копирование
результата образуют один атомарный узел анализа. Можно перейти в его начало или
обойти весь узел; нельзя попасть на аргумент, binding, MCALL или result copy.
Каждая инструкция всё равно отдельно разбирается и проверяется по роли.

Скалярные span выводятся из проверенных инструкций/сигнатур; их виды постоянны,
пересечения запрещены. Определённость анализируется отдельно: чтения требуют
факты, записи и нормальный результат вызова создают факты. Две32-битные маски
покрывают все64 span. Отдельный факт показывает, что перед вызовом на каждом
входящем пути была попытка LOAD; успех загрузки этим не предполагается.

На входе фактов нет. Слияния пересекают выходы всех предшественников. Убывающий
worklist находит неподвижную точку и в циклах: определение из будущей итерации не
становится определением первой. Требования чтений проверяются после сходимости.
Все границы узлов должны быть структурно достижимы; цели лежат внутри команды,
последняя инструкция остаётся EXIT. Число извлечений из очереди ограничено
132*число-инструкций; завершение самой программы не доказывается.

Анализ не выделяет heap/VM-объекты и публикует view только целиком. Временные
целочисленные факты не являются снимком живого REG, правом на native-чтение или
постоянной JIT-метаинформацией. Владение конструктора, pin cleanup, release/acquire,
карты GC, файловая политика и доказательство библиотеки сохраняются.

## Проверки

```sh
python3 utils/tests/dis64-scalar-client.py --cfg --limbo /host/limbo
python3 utils/tests/dis64-scalar-client-boot.py --cfg \
    --limbo /host/limbo --emu /root/emu/Linux/o.emu-g --root /root
python3 utils/tests/dis64-scalar-client-cfg-proof.py --limbo /host/limbo
for control in join load boundary high; do
    python3 utils/tests/dis64-scalar-client-cfg-proof.py \
        --limbo /host/limbo --control "$control"
done
```

Для ARM64/Linux QEMU используются прежние переменные компилятора/runner.15 пар
исходников проверяют nil guards, обе ветки diamond, ранний выход,0/1/много итераций,
reload, break/continue и полную ширину Big/Real. На платформу проходят1440 запусков
планировщика: C/RX клиента/библиотеки, обычный/растущий стек, кванты, отказы I/O и
admission, отключение JIT. ASan/UBSan проверяет конструктор тех же15 пар без
исполнения VM-инструкций.

Отдельно обе полные консоли проходят по60 C/RX OS-запусков, включая штатный выход
при отсутствии каждой библиотеки, и два контроля неверного результата провайдера.
21 независимый raw-вход проверяет отсутствующие определения на join/первом входе
цикла, переходы внутрь setup, ширину nil-сравнения, верхнюю половину маски и64/65
span. Четыре отключения predicate должны давать семантический exit10; повреждённый
код не исполняется. Прежние28 raw-входов/три контроля,17 линейных клиентов/1632
запуска и34 full-OS запуска остаются совместимы.

17 прежних importing dis64 совпадают с предыдущим компилятором побайтно;15 новых
исходников сохраняют классические bytes. AWM baseline остаётся14 accepted/346
refused с равенством classic/traced outputs. Это проверка исходников, а не запуск
AWM. Android/Bionic GUI APK, новый concurrent GC/FS proof и перенос обработчиков
сигналов/отладчика FlashVM здесь не заявляются.
