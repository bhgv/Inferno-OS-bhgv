# Возврат типизированных значений на native64

[English version](dis64-typed-returns.md). Продолжение
[переноса целых тел функций](dis64-typed-bodies.ru.md).

```limbo
count(n: int): int {
    total := 0;
    while(n > 0) { total += n; n--; }
    return total;
}
identity(text: string): string { return text; }
wide(x: big): big { return x; }
fraction(x: real): real { return x; }
octet(x: byte): byte { return x; }
items(xs: list of string): list of string { return xs; }
```

Объявления функций помещаются в интерфейс модуля. Полный компилируемый пример —
`utils/tests/dis64-typed-body.py`, исполнение обработчиками VM —
`utils/tests/native64-typed-body.c`.

Компилятор Limbo записывает результат через адрес FP[16]+0 старого кадра.
Перенос сохраняет существующие команды и заменяет адрес на полный указатель
в FP[32] нативного кадра. Размер byte остаётся 1 байт, int/fix — 4,
big/real и управляемые ссылки — 8. Для ссылок используется штатный MOVP.
Анализ графа управления требует определения результата на каждом достижимом
пути к RET: в точке слияния факты пересекаются. Инициализация только одной
ветви недостаточна. Возврат tuple/ADT пока отклоняет всё тело функции.

## Связывание с вызывающим кодом на C

`include/native64-typed-return.h` связывает два отдельных владеющих буфера
через существующие корневые `Native64Result`. Ячейка результата находится
после зарезервированных 64 байт вызывающего буфера. Проверяются границы,
выравнивание, размер, роль в карте GC, типы объектов и пустой адрес результата.
Перед записью повторно проверяются эти условия и совпадение полного адреса.
Отказ не выделяет память и не изменяет результат. Очистка идемпотентна.

Связка заимствует корневые guards, не приобретая отдельное владение или pin.
До очистки guards, их значения, типы и карты должны оставаться неизменными,
живыми и закреплёнными. Это синхронный локальный вызов под существующим
исключением VM; здесь нет аутентификации указателя, защиты от ABA, постоянного
отзыва доступа или конкурентного протокола времени жизни.

Проверки используют подготовленные владеющие буферы, реальные обработчики VM
и GC между инструкциями. Покрыты nil, Unicode/NUL, замена старой и той же ссылки,
настоящие списки, освобождение callee, контроль соседних байтов и отказы.
Это ещё не активные кадры Prog: общий production CALL/RET между модулями
и допуск образа модуля остаются следующими задачами.

## Формат отчёта и запуск проверок

```sh
python3 utils/tests/dis64-typed-body.py --limbo /path/to/limbo --awm
python3 utils/tests/native64-arguments.py --formatter --limbo /path/to/limbo \
    --omission typed-return-width --omission typed-return-map
```

При `LIMBO_DIS64_TYPED=1` частный JSON использует `inferno-typed-body-v2`.
`result` содержит `[вид_компилятора, размер]`; инструкция —
`[opcode, mode, source, middle, destination, return_contract]`.
Последний элемент равен нулю для обычной команды; для записи результата —
размер OR 16 при ссылочном типе (то есть 24 для ссылки размером 8).
Это частный контракт checked IR и тестового исполнения. Публичный формат
Dis64, номера команд и обычный байткод не меняются.

В исходниках AWM проходят 14 полных тел, отклоняются 346. Это анализ исходников;
запуск AWM, GUI APK и Android/Bionic JIT этой проверкой не подтверждаются.
