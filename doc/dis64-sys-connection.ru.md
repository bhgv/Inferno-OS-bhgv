# Использование Sys Connection в Dis64

[English](dis64-sys-connection.md).

Приватный файловый профиль `limbo -64l` теперь поддерживает полезный TCP-клиент:
проверку статуса dial, поля Connection.dfd/cfd/dir, запись/чтение байтов,
преобразование прочитанного префикса и сохранение буфера при следующем dial.
Используются существующие Inferno VM и JIT, без переноса DisVM и прокси.

Сохраните как `connection.b`. На loopback-порту 12345 нужен сервер, который
читает `ping`, отправляет `pong\n`, затем читает эхо клиента:

```limbo
implement ConnectionTrial;
include "sys.m";
ConnectionTrial: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    (status, c) := sys->dial("tcp!127.0.0.1!12345", nil);
    if(status < 0)
        return;
    b := array of byte "ping";
    n := sys->write(c.dfd, b, len b);
    b = array[16] of byte;
    n = sys->read(c.dfd, b, len b);
    if(n < 0)
        return;
    text := string b[:n];
    r := sys->werrstr(text);
    b = array of byte text;
    n = sys->write(c.dfd, b, len b);
}
```

```sh
limbo -I module -64l -o /build/connection.dis64 connection.b
/build/emu/Linux/o.emu-g -v -c 0 -r /build \
    -d /connection.dis64 -P '$Sys' -X dis64-managed-trial
```

Повторите с `-c 1` для запроса JIT. `werrstr` сохраняет текст, а не печатает его.
Read/write могут вернуть короткую длину. Пример отражает один read, а не полное
сетевое сообщение, и предполагает успешную маленькую запись. Прикладному
протоколу нужны свои цикл записи, framing, политика EOF и границы UTF-8.
Тестовый сервер допускает непустой отражённый префикс; отдельные C-тесты
принудительно задают короткое/ошибочное чтение и проверяют точные байты.

## Исходный код и кадр

Одна группа импортов может содержать dial, read, write, iounit и werrstr
в любом порядке. Она разрешается по сгенерированной метаинформации Sys.
Допускаются линейные полные вызовы, Word-операции и условный ранний выход
вроде `if(status < 0) return`. Отслеживаются один текущий Connection,
байтовый массив, преобразованная строка и две сохраняемые локальные Word.
Поля можно передавать непосредственно: `sys->iounit(c.cfd)`,
`sys->werrstr(c.dir)`, `array of byte c.dir` используют настоящий тип поля.

Общие ветвления/циклы, копирование Connection ADT, изменение полей и произвольные
алиасы пока отклоняются. Временный срез `string b[:n]` завершает доступ к старому
локальному массиву в этом профиле; перед повторным использованием присвойте
этому локальному новый массив. Сохраняется прежнее ограничение одного текущего
массива. Прежний профиль только dial и его байтовые образы не изменены.

| Смещение | Назначение |
| --- | --- |
| 64 / 72 | Корни строковых аргументов |
| 80 | Word статуса dial |
| 84..87 | Немаркированное заполнение tuple |
| 88 / 96 / 104 | Корни data FD / control FD / directory |
| 112 / 120 | Корни массива / преобразованной строки |
| 128 | Word результата native scalar-вызова |
| 132 / 136 | Сохраняемые локальные Word |

Кадр занимает 144 байта, точная карта `00 df 00`. Третий сериализованный тип —
проверенный байтовый дескриптор; до JIT он заменяется каноническим Tbyte.
Binder полного адреса различает 32-байтовый tuple на FP80 и четырёхбайтовый
результат на FP128, проверяя адрес и геометрию callee. Scalar-результат не может
перезаписать сохраняемый Word на FP132.

Загрузчик заново вычисляет инициализацию status, Connection, массива, строки
и Word. Scalar-вызов не создаёт поля Connection; запись указателя не создаёт
целого значения. Переход не может войти в подготовку вызова или пропустить
обязательное определение. Неизвестные методы, повреждённые карты, подмена
типа равной ширины и неполные вызовы отклоняются до выделения памяти.
Новых публичных полей формата, managed IDs и инструкций нет.

## Проверки и Android

```sh
python3 utils/tests/dis64-sys-fixed-gc.py --limbo /host/tools/limbo
python3 utils/tests/dis64-sys-connection.py --limbo /host/tools/limbo \
    --root /build --emu /build/emu/Linux/o.emu-g
python3 utils/tests/awm-native64-preflight.py --limbo /host/tools/limbo
```

Owning gate добавляет 24 C/JIT/GC исполнения, 39 отказов повреждённых образов,
18 native/5 heap отказов с откатом конструктора. Ещё шесть отказов при живом
Connection сохраняют его tuple при откате выделения массива/строки. Три контрольных удаления
проверяют необходимость инициализации Connection, различения FD/Word и карты
корней смешанного кадра. Прежние fixed Sys и dial тесты остаются в наборе.
Консольный gate проверяет восемь настоящих TCP-соединений, обмен байтами,
UTF-8 запросы, эхо префикса, замену соединения и два отказа dial с ранним выходом,
в C-режиме и с запросом JIT. Он включён и в общий paired-console gate.

Android ARM64 остаётся первой прикладной целью. Консольные проверки относятся
к AMD64 и Linux ARM64/QEMU, не к Android/Bionic GUI или устройству. AWM preflight
теперь проверяет и scalar `-64`, и managed `-64l`: все шестнадцать стартовых
модулей ещё требуют общего managed lowering/linkage, входов с аргументами,
тел библиотек и таблиц исключений sh. Работающий ограниченный сетевой клиент
не закрывает эту общую границу AWM.
