# Native64: полный Wmclient и исполнение создания окна

Неизменённый `appl/lib/wmclient.b` теперь принимается целиком: 21/21 тела,
792 инструкции, пять таблиц импортов и 11 вариадических вызовов. Обычный
Dis по-прежнему выдаётся побайтно прежним; 32-битные пути сохранены.

## Что добавлено

* Свежий ref/channel результат импорта прямо в root-поле Window. Разрешён
  именованный формальный или локальный владелец; глобальный и compiler
  temporary владелец закрыты. Перед выдачей адреса runtime проверяет
  живой Type Window: 128 байт, карта 92/c4, точное разрешённое поле.
* Полные приватные layouts Tk.Toplevel (48 байт) и Wmclient.Window (128).
  `ref blankwin` использует отдельный mapped clone, непосредственно после
  выделения точного Window. Проверяются весь MP span, карта roots и запрет
  входящего перехода на clone.
* Цепочки root-полей Window/Wmcontext/Context/Display/Toplevel при подготовке
  аргумента. Один mapped temporary, максимум восемь переходов, передача
  аргумента и обязательная очистка nil образуют единую проверяемую цепочку.
* Raw Point/Rect копии Image/Window → Window, ref-field копии между полными
  известными layouts, Word/String преобразования полей Window и создание
  канала `Window.ctl`.
* Вычисляемые Point/Rect аргументы из нескольких копий/Word операций,
  канонический Draw.Chans и Image Word поле как внешний аргумент.
* До восьми String temporaries в составном аргументе с обязательной очисткой
  каждого; byte-array slice → String аргумент с очисткой временного root.

Это приватные compiler/runtime аннотации. Чтение произвольных пользовательских
ADT или нового сериализованного формата Dis ими не разрешается.

## Исполнение и проверка

`utils/tests/native64-wmclient-module.py` включён в native64-port и оба задания native64-typed-calls CI. Он строит
весь исходный модуль, получает signatures и import frames из канонических
headers и проверяет исходные операнды независимым classic decoder.
Проверяются 138 искажений новых инструкций и 110 искажений variadic records.
Runtime отвергает 46 неверных mode/extent вариантов до выделения памяти.
Все 195/196 точек отказа конструктора C/JIT дают атомарный rollback.

168 сквозных прогонов исполняют оригинальные `init`, `window`, `readscreenrect`,
`sizetb`, `Window.wmctl`, `wmreq`, `recvimage`, `putimage` и `drawborder` по достижимым веткам:

* интерпретатор и amd64 JIT, кванты 1/3/1000;
* Plain и окно с titlebar; настоящий VM канал управления и mapped Window;
* `/chan/wmrect` недоступен, пустое чтение, успешное чтение 48-байтного
  буфера и срез в строку с передачей в s2r;
* focus/size/move/rect/default запросы; точные Tk/Titlebar строки,
  преобразования чисел, многовременные String выражения и срез запроса;
* путь без оконного менеджера через Window → Wmcontext → Context → Display
  → Image, Screen.allocate, Image для заголовка/клиента и точная геометрия
  четырёх сторон рамки;
* подключённый connfd и реальный вариадический gateway с контролируемым
  fprint; буферизованный images канал отдаёт сначала nil, затем Image;
* сохранность полей и полное освобождение всех объектов/модулей/каналов.

Rect.size/inset/dx/dy взяты из производственного `libinterp/geom.c`. Sys I/O, Tk,
Titlebar и Wmlib в этом тесте — контролируемые сервисы. Тест не запускает
настоящую графическую систему и не доказывает исполнение всех веток
принятых функций. Cursor loop, повторная замена изображения и все варианты
ошибок графических сервисов здесь не исполняются.

Активные контроли меняют адрес root-результата Window, нижнюю границу
byte slice и поле назначения Image → Window Rect. Ошибку обнаруживают
проверки результата исходного кода.
Сохранены предыдущие call-prep, String preparation, Window geometry,
Wmsrv и AWM cluster regression gates. Чистая amd64 console сборка,
Dis64 pair boot и emuinit boot проходят.

## Оставшиеся зависимости

Это крупный шаг к AWM, но не готовый графический сеанс. Текущий приём
полных исходников: AWM 20/20, Wmsrv 34/34, Wmclient 21/21, String 21/21,
Bufio 27/27; Wmlib 11/25, [Titlebar 7/7](native64-titlebar-module.ru.md) и Winplace 8/21. До реального окна
нужно довести эти зависимости и подключить настоящие Draw/Tk сервисы.
Android arm64 GUI и arm64/riscv64 исполнение этим amd64 тестом не проверены.
