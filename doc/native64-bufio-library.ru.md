# Полная исходная библиотека Bufio в native64

Неизменённый `appl/lib/bufio.b` теперь проходит checked compiler для всех
27 функций. Публичные методы, включая `Iobuf.*`, экспортируются с исходными
именами и хешами из `module/bufio.m`; private helpers исполняются из Limbo.

Введены закрытые раскладки пользовательских ADT. `Bufio.Iobuf` занимает
56 байт, с GC-корнями fd/buffer на смещениях 0/8; index/size/dirty на
16/20/24, bufpos/filpos на 32/40, lastop/mode на 48/52.
Частная запись Filler занимает 24 байта и содержит три корня.
Для очередей Wmsrv также описаны точные раскладки; полного runtime-прогона
Wmsrv этот этап не утверждает.

Новые операции сохраняют Word32 и byte ширины, различают raw поля и корни,
проверяют границы кадров и полей до материализации. Записи выделяются через
отдельные private Type с проверенными GC maps. Индексирование byte-массива
использует непосредственного потребителя адреса в FP48: переходы и таблицы
не могут войти между этими двумя инструкциями. Поддержаны срезы/copy массивов
и подготовка аргументов из полей записей, включая срез pending argument.

`BufioFill.fill` вызывается через настоящий MFRAME/MCALL из поля Filler.fill.
Его геометрия и хеш берутся из отдельного сгенерированного интерфейса, а не
из отсутствующего в classic LOAD списке callback import table. Допуск
ограничен именно этим полем закрытой раскладки. Остальные непрямые источники
модулей остаются закрыты. Sys.byte2char использует результат из трёх Word32.

Проверка `utils/tests/native64-bufio-library.py`:

- все 27 исходных тел и неизменённые classic bytes;
- хеши и полные кадры Sys/BufioFill из настоящих интерфейсов;
- 1614 независимых повреждений compiler report и 1614 runtime-отказов
  повреждённых метаданных до выделения памяти;
- 648 публичных вызовов C/JIT, все 27 тел реально посещены через VM fetch;
- кванты 1/3/1000, чтение порциями 1/7/8192 байта, большая запись,
  flush, seek, EOF, offset, Unicode, pushback, строковые и массивные буферы;
- настоящий код Sys.byte2char/char2byte и VM array/String operations;
- контролируемый файловый I/O и callback, ошибки чтения и полное освобождение;
- все 83/84 точки отказа выделения C/JIT конструктора;
- активный контроль утраты GC-корня buffer в private Iobuf descriptor.

Публичные вызовы используют один сохраняющий состояние экземпляр Bufio:
как и в Limbo, отдельный linkmod создаёт отдельные module data. Это существенно
для Sys и списка fillers. Файловый backend стенда работает в памяти.

```sh
python3 utils/tests/native64-bufio-library.py --limbo /path/to/limbo
```

Это checked native module builder с полным исходником библиотеки. Admission
всего графа native64-файлов, реальное окно AWM и запуск Android ещё не подтверждены.
Classic Dis и 32-битные исходники сохранены.
