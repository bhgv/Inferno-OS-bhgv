# Пользовательские модули в приватном managed-профиле файлов

Проверочный профиль String/List теперь допускает собственные имена модулей и
функций. Пока поддерживаются только две формы функций из примера ниже.
Обычный `-64`, произвольные managed-вызовы, массивы, ADT и Android AWM остаются
за пределами этого профиля. [English version](dis64-managed-modules.md).

Сохраните интерфейс в `box.m`:

```limbo
Box: module {
    pack: fn(payload: string): list of string;
    unpack: fn(items: list of string): string;
};
```

Реализация `box-provider.b`:

```limbo
implement Box;
include "box.m";
pack(payload: string): list of string
{
    return payload :: nil;
}
unpack(items: list of string): string
{
    return hd items;
}
```

Вызывающий модуль `box-caller.b`:

```limbo
implement Caller;
include "box.m";
Caller: module { init: fn(); };
init()
{
    lib := load Box "/box-provider.dis64";
    items := lib->pack("Grüße 世界");
    text := lib->unpack(items);
    items = lib->pack("second\0line");
    text = lib->unpack(items);
}
```

Скомпилируйте нативным host-компилятором и запустите консольным эмулятором,
собранным с native64 managed-file профилем. Оба результата должны лежать внутри
корня `/build`:

```sh
/host/tools/limbo -H -M Box box.m > box-native64.h
/host/tools/limbo -I . -64m -o /build/box-provider.dis64 box-provider.b
/host/tools/limbo -I . -64l -o /build/box-caller.dis64 box-caller.b
/build/emu/Linux/o.emu-g -c 0 -v -r /build \
    -d /box-caller.dis64 -P /box-provider.dis64 \
    -X dis64-managed-trial
```

Пример завершается без печати. Повторите с `-c 1` для проверки режима с
запрошенным JIT; это ещё не доказательство исполнения всего caller в машинном
коде. Путь в `load` должен точно совпадать с `-P`. Заголовок нужен для проверки
ABI; для этих Limbo-реализаций писать C-расширение не требуется.

`limbo -H` вычисляет сигнатуры типов из `.m`. Загрузчик проверяет структурные
сигнатуры, кадры, карты указателей и код реализации, затем точно сопоставляет
имена модуля и экспортов. Переименование provider без пересборки caller
отклоняется даже при совпадении типов. Здесь кадр занимает 72 байта, managed-
аргумент находится по смещению 64, карта указателей — `{0x00,0x80}`.
Фактические константы сигнатур видны в сгенерированном заголовке; тип аргумента
не выводится из имени функции.

Для caller с входным аргументом опция `-A` выбирает тип начального значения по
проверенной сигнатуре: строка либо одноэлементный список строк. Даже если
функции назвать `quoted` и `unquoted` в обратном направлении, тип остаётся
правильным. Без `-A` входной список равен nil и `hd` завершится ошибкой.
Приведённому выше `init()` начальный аргумент не нужен.

Допускается один экспорт каждого направления, всего до двух экспортов и
импортов, тела `payload :: nil` и `hd items`, а также поддержанные формы
локальных переменных, алиасов и очистки через nil. Идентификаторы модуля и
функций ограничены 255 ASCII-символами. Имена и метаданные копируются во
владение загрузчика; временные буферы каталога не остаются в живых связях.
Для caller в файле используйте `-64l`: prelinked-caller с `-64m` сохраняет
канонический профиль String.

Действуют прежние [ограничения литералов и правила владения](dis64-managed-literals.ru.md):
до 32 материализованных строк, до 255 рун в строке, суммарно 1024 руны и до
32 вызовов. Смешанные вызовы builtin-модулей и произвольная GUI-программа пока
не допускаются.

Проверки интерфейсов и настоящего сборщика мусора:

```sh
python3 utils/tests/dis64-pair-boot.py --root /build \
    --emu /build/emu/Linux/o.emu-g --limbo /host/tools/limbo \
    --managed-module-only
python3 utils/tests/dis64-numeric-gc.py --managed --limbo /host/tools/limbo
```

Проверки генерируют настоящие C-заголовки из `.m`, компилируют проверки
размеров кадров, сверяют весь CODE и сигнатуры импортов, запускают произвольные
и переставленные имена и идентификаторы длиной 255. Несовпадающие и
некорректные имена отклоняются до планирования. Проверяются точные значения,
типы начальных объектов, принудительный GC и очистка при отказах выделения
памяти. Контрольные поломки убирают публикацию корней и возвращают выбор типа
по имени: оба теста обязаны обнаружить ошибку. Для cross-запуска задаются `CC`,
`NATIVE64_ARCH`, `NATIVE64_RUNNER`, для санитайзеров — `NATIVE64_CFLAGS`.
