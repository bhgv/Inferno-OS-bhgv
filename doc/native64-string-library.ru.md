# Полная исходная библиотека String в native64

Проверяется неизменённый `appl/lib/string.b`: все 21 тело, включая 17
публичных функций из `module/string.m`. Алгоритмы остаются на Limbo;
исполняются настоящие VM-операции из `libinterp/string.c` и `xec.c`.

Общий ABI теперь поддерживает `(string,string)`, `(int,string)`,
`(big,string)`, `(real,string)` и внутренний результат из трёх `int`.
Два корня используют прежний контракт 48; смешанная пара — контракт 16,
16 байт с единственным корнем на смещении 8; три Word32 — контракт 12.
Числовая часть смешанной пары остаётся raw, включая выравнивающий промежуток
после `int`. Контракт 16 разделяет карту с ALT reply 136, но не его семантику.

Также проверены запись символа в строку, срез непосредственно в результат,
индексирование строки непосредственно в аргумент локального вызова и
преобразование Word32 в аргумент `real`. Привязки результата `ILEA` имеют
теги `128|contract`: числовые коды аргументов различаются с ними по opcode.

`utils/tests/native64-string-library.py` проверяет:

- независимое чтение classic Dis, хеши интерфейса и побайтовое сохранение
  обычной компиляции, 588 повреждений отчёта;
- 528 сценариев C/JIT при квантах 1, 3 и 1000, ASCII, Rune и nil;
- фактическое посещение всех 21 исходных тел через VM fetch;
- точные строки, списки, int32/int64, radix, real, Inf/NaN;
- неизменность аргументов, соседние байты Word32, полное освобождение;
- 215 отказов повреждённых метаданных до выделения памяти;
- откат всех 51/52 точек выделения в C/JIT конструкторе;
- активный контроль: удаление проверки смещения числового результата
  обязательно приводит к обнаружению принятой повреждённой записи.

Запуск:

```sh
python3 utils/tests/native64-string-library.py --limbo /path/to/limbo
```

Это выполнение полной библиотеки через checked native module builder.
Обычная загрузка всего библиотечного графа из native64 файлов и запуск
полного AWM ещё не подтверждены. 32-битные исходники и classic Dis сохраняются.
