# Строковые литералы и самостоятельный managed-модуль

Явный профиль компилятора `-64l` теперь принимает `init()` без аргументов и до 32
строковых литералов. Литералы записываются в Rune32-пул `.dis64`; загрузчик создаёт
отдельный управляемый объект String для каждого корня и помещает его в MP с корректной картой ссылок до
старта программы. Внешняя подстановка строки через `-A` больше не нужна.
Это по-прежнему ограниченный String/List-профиль, запускаемый с
`-X dis64-managed-trial`. Обычный `-64`, общая управляемая линковка и запуск
Android AWM этим изменением не реализованы.

Полный пример провайдера и вызывающего модуля, команды сборки и проверки
приведены в [английской версии](dis64-managed-literals.md). Провайдер в примере
упаковывает строку в одноэлементный список и извлекает её обратно; это учебный
поднабор интерфейса String, а не реализация всей библиотеки.

Минимальное тело вызывающего модуля:

```limbo
init()
{
    lib := load String "/literal-provider.dis64";
    items := lib->unquoted("Grüße 世界");
    value := lib->quoted(items);
    items = lib->unquoted("second\0line");
    value = lib->quoted(items);
    lib = load String "/literal-provider.dis64";
    items = lib->unquoted("Grüße 世界");
    value = lib->quoted(items);
}
```

Поддерживаются локальные псевдонимы, повторная передача того же литерала и
повторный LOAD. Nil хранится отдельно; вызов `quoted(nil)` сохраняет ошибку
разыменования nil. Пустой литерал и его локальные псевдонимы сохраняют
представление nil, выбранное промежуточным кодом Limbo. Отдельно проверяется
ненулевая пустая запись Rune32-пула: загрузчик создаёт для неё пустой объект
String, а не отсутствующую ссылку. Встроенный NUL в данных строки сохраняется;
в пути LOAD он запрещён, чтобы путь не обрезался незаметно.

Ограничения: до 32 материализуемых строк, до 255 рун в каждой и до 1024 рун
суммарно, до двух импортов и до 32 вызовов. MP0 — модуль, MP8 — nil, MP16 —
путь LOAD, MP24+8*i — строка i. Карта покрывает все 3+n ссылок, включая старшие
байты; для 32 строк это 280 байт данных и карта `ff ff ff ff e0`. Каждый корень
должен использоваться проверенным кодом. Совпадение числовых смещений MP и FP
не означает совпадения адресов: это разные пространства операндов.

Rune32 копируются без преобразования через UTF-8, включая NUL и любые
signed32-биты. Даже одинаковые записи пула получают отдельные объекты.
Новых публичных тегов формата не добавлено; прежние изображения с одной
строкой сохраняют байты и размещение.

Тесты запускают настоящие `.dis64` через полный планировщик. Отдельная проверка
использует реальные конструкторы и GC: сравнивает значения рун, проверяет
сохранность корня после сборки и отсутствие утечек при каждом отказе выделения
памяти. Запуски собирают мусор после каждого кванта и проверяют, что
итоговая строка или голова списка — ожидаемый исходный объект из MP, а все
остальные корни также сохранились. Независимые байтовые оракулы проверяют весь
CODE, порядок аргументов и карты на границах от 2 до 32 строк. Контроль с намеренно
удалённой публикацией корня обязан завершиться на
соответствующей проверке. Режим `-c 1` проверяется отдельно, но сам по себе не
доказывает исполнение всего вызывающего модуля машинным кодом.
