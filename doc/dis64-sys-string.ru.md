# Строковый аргумент из Dis64 во встроенный Sys

Приватный файловый профиль `-64l` теперь вызывает настоящий фиксированный
`Sys->werrstr(string): int` через `LOAD $Sys`, MFRAME и MCALL. Сериализованная
строка проходит в native-кадр builtin-модуля, результат возвращается как Word.
Обычный `-64`, вариадический print, смешанные builtin-группы и Android AWM
пока не включены. [English version](dis64-sys-string.md).

Сохраните как `sys-text.b`:

```limbo
implement SysText;
include "sys.m";
SysText: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    message := "Grüße 世界";
    saved := message;
    message = nil;
    status := sys->werrstr(saved);
    sys = load Sys Sys->PATH;
    status = sys->werrstr("second\0suffix");
}
```

Нужны нативные host-инструменты и консольный эмулятор с native64 managed-file
и Sys I/O профилями. Выходной файл должен лежать внутри корня эмулятора:

```sh
/host/tools/limbo -I module -64l -o /build/sys-text.dis64 sys-text.b
/build/emu/Linux/o.emu-g -v -c 0 -r /build \
    -d /sys-text.dis64 -P '$Sys' -X dis64-managed-trial
```

Повторите с `-c 1` для запроса JIT. В обоих режимах проверяется завершение и
очистка планировщика; это не означает исполнения всех инструкций машинным кодом.
`werrstr` меняет текст ошибки текущего процесса и возвращает ноль. Печати нет.
Во втором вызове VM сохраняет всю строку вместе с NUL; существующий C API
текста ошибки видит `second` до NUL. Длинный текст обрезается прежним `kstrcpy`.

`Sys` — описатель интерфейса Limbo, `Sys->PATH` даёт `$Sys`. Интерпретатор
обрабатывает только сериализованный Dis64. Компилятор записывает приватную
структурную сигнатуру String→Word. Resolver проверяет реальный экспорт из
сгенерированных `limbo -H module/sys.m` метаданных: адрес C-функции, контрольный
legacy-хэш, кадр 72 байта и карту аргумента `{0x00,0x80}`. Совпадение одного
хэша не разрешает вызов.

Кадр caller занимает 80 байт. FP64 владеет текущим String-аргументом, FP72 —
четырёхбайтовый Word-результат с немаппированным четырёхбайтовым хвостом.
Проверенный callback записывает полный восьмибайтовый адрес результата в
подготавливаемый native-кадр. Проверяются карта caller, положение на стеке и
карта аргумента callee. Строковый корень живёт через конвертацию и GC, а
скалярный результат не считается указателем. Повторный вызов штатно заменяет
принадлежащую caller ссылку аргумента.

MP0 хранит загруженный модуль, MP8 — nil, MP16 — принадлежащий модулю путь
`$Sys`, MP24+8*i — независимые строки. Допускаются до 32 корней, до 255 рун в
строке, суммарно 1024 руны и до 32 последовательных вызовов. Поддержанные
локальные алиасы, nil и повторные LOAD проходят те же проверки producer, что
и в профиле именованных String/List-модулей. Вход — `init()` без аргумента;
опциональный seed `-A` игнорируется. Использование Word-результата в выражении
или ветвлении, другие методы Sys и смешанные file/builtin-вызовы пока
отклоняются этим профилем.

Проверки точных байтов, полного эмулятора и настоящего GC:

```sh
python3 utils/tests/dis64-sys-string.py --limbo /host/tools/limbo \
    --root /build --emu /build/emu/Linux/o.emu-g
python3 utils/tests/dis64-sys-string-gc.py --limbo /host/tools/limbo
```

Проверка владения использует настоящие `Sys_werrstr`, `string2c`, `kstrcpy`,
resolver, linker, привязку кадра и сборщик мусора. Проверяются точные значения
Unicode/NUL/nil/длинного текста, запись ровно четырёх байтов результата и
сохранность соседних байтов, GC после каждого кванта VM, все отказы выделения
при конструировании и ошибка конвертации уже после входа MCALL в native-кадр.
Некорректные код, карты, имена и сигнатуры отклоняются до выделения владельцев.
Контрольные поломки убирают запись результата и публикацию литерала; тесты
обязаны обнаружить ошибку явной проверкой значения. Для cross-запуска задаются
`CC`, `NATIVE64_ARCH`, `NATIVE64_RUNNER`, для флагов — `NATIVE64_CFLAGS`.
