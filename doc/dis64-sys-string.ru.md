# Строковый аргумент из Dis64 во встроенный Sys

Приватный файловый профиль `-64l` теперь вызывает настоящий фиксированный
`Sys->werrstr(string): int` через `LOAD $Sys`, MFRAME и MCALL. Та же фиксированная группа String→Word
допускает `chdir` и `remove`, а также смешанные вызовы `millisec`, `sleep`
и `dup`, а также `fildes` и `iounit` — до четырнадцати разных импортов, включая `open`, `create`, `read` и `write`. Сериализованная
строка проходит в native-кадр builtin-модуля, результат возвращается как Word.
Обычный `-64`, вариадический print, другие сигнатуры builtin-вызовов и Android AWM
пока не включены. [English version](dis64-sys-string.md).

Сохраните как `sys-text.b`:

```limbo
implement SysText;
include "sys.m";
SysText: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    message := "Grüße 世界";
    saved := message;
    message = nil;
    status := sys->werrstr(saved);
    sys = load Sys Sys->PATH;
    status = sys->werrstr("second\0suffix");
}
```

Нужны нативные host-инструменты и консольный эмулятор с native64 managed-file
и Sys I/O профилями. Выходной файл должен лежать внутри корня эмулятора:

```sh
/host/tools/limbo -I module -64l -o /build/sys-text.dis64 sys-text.b
/build/emu/Linux/o.emu-g -v -c 0 -r /build \
    -d /sys-text.dis64 -P '$Sys' -X dis64-managed-trial
```

Повторите с `-c 1` для запроса JIT. В обоих режимах проверяется завершение и
очистка планировщика; это не означает исполнения всех инструкций машинным кодом.
`werrstr` меняет текст ошибки текущего процесса и возвращает ноль. Печати нет.
Во втором вызове VM сохраняет всю строку вместе с NUL; существующий C API
текста ошибки видит `second` до NUL. Длинный текст обрезается прежним `kstrcpy`.

`Sys` — описатель интерфейса Limbo, `Sys->PATH` даёт `$Sys`. Интерпретатор
обрабатывает только сериализованный Dis64. Компилятор записывает приватную
структурную сигнатуру String→Word. Resolver проверяет реальный экспорт из
сгенерированных `limbo -H module/sys.m` метаданных: адрес C-функции, контрольный
legacy-хэш, кадр 72 байта и карту аргумента `{0x00,0x80}`. Совпадение одного
хэша не разрешает вызов.

Кадр caller занимает 80 байт. FP64 владеет текущим String-аргументом, FP72 —
четырёхбайтовый Word-результат с немаппированным четырёхбайтовым хвостом.
Проверенный callback записывает полный восьмибайтовый адрес результата в
подготавливаемый native-кадр. Проверяются карта caller, положение на стеке и
карта аргумента callee. Строковый корень живёт через конвертацию и GC, а
скалярный результат не считается указателем. Повторный вызов штатно заменяет
принадлежащую caller ссылку аргумента.

MP0 хранит загруженный модуль, MP8 — nil, MP16 — принадлежащий модулю путь
`$Sys`, MP24+8*i — независимые строки. Допускаются до 32 корней, до 255 рун в
строке, суммарно 1024 руны и до 32 последовательных вызовов. Поддержанные
локальные алиасы, nil и повторные LOAD проходят те же проверки producer, что
и в профиле именованных String/List-модулей. Вход — `init()` без аргумента;
опциональный seed `-A` игнорируется. Расширенный кадр ниже допускает Word-выражения и управление потоком.
`werrstr`, `chdir` и `remove` допускаются в одной группе; другие методы и
смешанные file/builtin-вызовы пока не допускаются.

Проверки точных байтов, полного эмулятора и настоящего GC:

```sh
python3 utils/tests/dis64-sys-string.py --limbo /host/tools/limbo \
    --root /build --emu /build/emu/Linux/o.emu-g
python3 utils/tests/dis64-sys-string-gc.py --limbo /host/tools/limbo
```

Проверка владения использует настоящие `Sys_werrstr`, `string2c`, `kstrcpy`,
resolver, linker, привязку кадра и сборщик мусора. Проверяются точные значения
Unicode/NUL/nil/длинного текста, запись ровно четырёх байтов результата и
сохранность соседних байтов, GC после каждого кванта VM, все отказы выделения
при конструировании и ошибка конвертации уже после входа MCALL в native-кадр.
Некорректные код, карты, имена и сигнатуры отклоняются до выделения владельцев.
Контрольные поломки убирают запись результата и публикацию литерала; тесты
обязаны обнаружить ошибку явной проверкой значения. Для cross-запуска задаются
`CC`, `NATIVE64_ARCH`, `NATIVE64_RUNNER`, для флагов — `NATIVE64_CFLAGS`.

## Word-результаты, условия и циклы

Сохраните пример как `sys-loop.b`. Он делает три вызова внутри цикла и один
после него. Печати нет. Для запроса JIT замените `-c 0` на `-c 1`.

```limbo
implement SysText;
include "sys.m";
SysText: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    n := 0;
    status := 0;
    while(n < 3){
        status = sys->werrstr("tick");
        if(status != 0)
            return;
        n++;
    }
    status = sys->werrstr("done");
}
```

```sh
/host/tools/limbo -I module -64l -o /build/sys-loop.dis64 sys-loop.b
/build/emu/Linux/o.emu-g -v -c 0 -r /build \
    -d /sys-loop.dis64 -P '$Sys' -X dis64-managed-trial
python3 utils/tests/dis64-pair-boot.py --root /build \
    --emu /build/emu/Linux/o.emu-g --limbo /host/tools/limbo \
    --sys-string-flow-only
python3 utils/tests/dis64-sys-flow-gc.py --limbo /host/tools/limbo
```

Расширенный producer поддерживает Word-арифметику и побитовые операции,
сравнения, условные вызовы, циклы с break/continue, ранний return из void-входа,
короткое замыкание и вложенные выражения с `werrstr`. Живые результаты
сохраняются через последующие вызовы. Начальный LOAD остаётся первым,
повторные LOAD сохраняют порядок относительно скалярных операций.
Прежние прямолинейные образы с кадром 80 байт остаются побайтово прежними.

Расширенный кадр занимает 112 байт с той же картой `{0x00,0x80}`:

| Ячейка | Назначение |
| --- | --- |
| FP64 | Принадлежащий caller String-аргумент |
| FP80, FP84, FP88 | Три постоянные Word-ячейки |
| FP104 | Четырёхбайтовый Word-результат |
| FP108 | Немаппированный хвост результата |

Word-операции могут обращаться только к выделенным числовым ячейкам.
Привязка полного адреса результата проверяет кадры caller 80/112 байт и
проверенные размеры native callee из таблиц ниже. Число и его хвост не становятся GC-корнями.
Компилятор и загрузчик проверяют определённость значений ограниченным
решателем пересечения фактов на CFG, включая путь с нулём итераций цикла.
Переход может входить в скалярный шаг, последующий LOAD или начало полного
блока «аргумент + вызов». Нельзя пропускать публикацию аргумента, входить в
подготовленный кадр или повторно входить в начальный LOAD. Каждая инструкция
должна быть структурно достижима.

Ограничения — 32 статических места вызова, 64 события Word/LOAD и три
постоянные Word-ячейки. Цикл может выполнять одно место вызова многократно.
Лишние одновременно нужные числовые значения отклоняются. Присваивания и
алиасы локальных String в функции с ветвлениями пока консервативно запрещены:
текущая проверка идентичности указателей не объединяет такие значения на
рёбрах CFG. В условном вызове или цикле передавайте литерал либо nil;
прямолинейные String-алиасы работают по-прежнему. Описанное ниже расширение
добавляет фиксированные числовые аргументы; общий и вариадический Sys пока не допускаются.

Проверка владения сверяет настоящую последовательность текстов ошибки и
число вызовов, 32-битное переполнение и побитовые выражения, выбор ветвей,
вложенные вызовы, нормальное/ошибочное завершение и GC после каждого кванта.
Независимые CFG-примеры отклоняют недостающие определения на слияниях,
определения только внутри цикла, чтение корня/хвоста и вход внутрь подготовки
вызова до выделения владельцев. Контрольные поломки заменяют пересечение
фактов объединением и убирают native-запись результата; обе обязаны упасть на
явной смысловой проверке. Отдельно проверяются отказы конструкторов и ошибка
конвертации после входа в вызов с новым 112-байтовым кадром caller.

## Группа фиксированных native-функций

Проверки воспроизводятся командами `python3 utils/tests/dis64-sys-groups.py --limbo /host/tools/limbo --root /build --emu /build/emu/Linux/o.emu-g`
и `python3 utils/tests/dis64-sys-groups-gc.py --limbo /host/tools/limbo`.
Они покрывают все шесть независимо переставленных порядков импортов,
соответствие ordinal в MFRAME/MCALL, различение имён методов при равных
структурных типах, кадры 80/112 байт, настоящие статусы namespace-операций
и удаление файла, созданного внутри нового временного каталога под корнем
эмулятора. Компилятор сохраняет свой канонический порядок импортов;
независимые перестановки wire-записей проверяют runtime.

Проверка владения вызывает настоящие `Sys_chdir`/`Sys_remove` с контролируемой
границей OS. Она принудительно запускает GC при release и внутри native-операции,
меняет заимствованные поля pending frame после snapshot и проверяет исходный
адрес результата и точный четырёхбайтовый статус. Конвертация String, способная
выделять память, теперь выполняется при удержанной VM до release: её отказ
не вызывает OS-операцию и сохраняет баланс release/acquire. Используется
существующая схема потоков и планировщика. См. [загрузку модулей](dis64-module-loading.ru.md): LOAD не вызывает init.


## Смешанные фиксированные вызовы String и Word

Один caller может импортировать `werrstr`, `chdir`, `remove`, `millisec`,
`sleep`, `dup`, `unmount` и `bind` через общий модуль `$Sys` и существующий linker. Отдельной
загрузки для каждого метода и автоматического вызова `init` нет.

| Методы | Аргументы | Native-кадр | Карта указателей |
| --- | --- | --- | --- |
| `millisec` | нет | 64 байта | `00` |
| `sleep` | один Word | 72 байта | `00 00` |
| `dup` | два Word | 72 байта | `00 00` |
| `werrstr`, `chdir`, `remove` | одна String | 72 байта | `00 80` |

Все возвращают четырёхбайтовый Word через проверенный полноразмерный адрес.
Числовые аргументы занимают native-смещения 64/68 и не становятся корнями GC.
Смешанный caller использует описанный выше кадр 112 байт, даже без строковых
аргументов. Компилятор и загрузчик требуют инициализации каждого числового
аргумента на всех входящих путях. Запись аргумента в pending frame не определяет
значение в caller. Имя, сигнатура, размер и карта сгенерированного native-входа
проверяются до выделения владеющего модуля.

Сохраните как `sys-fixed.b`; команды компиляции и запуска выше применяются
с заменой `sys-text` на `sys-fixed`:

```limbo
implement SysFixed;
include "sys.m";
SysFixed: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    stamp := sys->millisec();
    status := sys->werrstr("start");
    status = sys->sleep(stamp-stamp);
    status = sys->dup(-1, -1);
    if(status < 0)
        status = sys->werrstr("invalid descriptor");
}
```

Запускайте `utils/tests/dis64-sys-fixed.py` с теми же `--limbo`, `--root`,
`--emu` и необязательным `--runner`, что и групповую проверку. Проверка владения:
`python3 utils/tests/dis64-sys-fixed-gc.py --limbo /host/tools/limbo`.
Она вызывает настоящие C-функции с контролируемой границей OS, запускает GC,
проверяет снимки аргументов, точные Word-результаты, перестановки импортов,
вложенные вызовы, циклы, перезагрузку и откат конструкторов. Контрольная поломка
анализа определений обязана провалить допуск. Это ещё не запуск полного sh/AWM
и не подтверждение native JIT для каждой инструкции.


## Два строковых аргумента и смешанный кадр

Тот же путь загрузки и связывания теперь допускает `unmount(string, string): int`
и `bind(string, string, int): int`. Native-кадр `unmount` занимает 80 байт,
`bind` — 88 байт; обе карты равны `00 c0`. Строки лежат по смещениям 64/72,
флаги `bind` — по смещению 80. В caller обе строки отдельно удерживаются
корнями FP64/FP72 (карта `00 c0`, размер 112), числовые ячейки FP80/84/88 и
результат FP104 остаются вне карты.

```limbo
implement SysPair;
include "sys.m";
SysPair: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    status := sys->bind("/dis", "/dis", Sys->MAFTER);
    if(status == 0)
        status = sys->unmount("/dis", "/dis");
    status = sys->werrstr("namespace calls completed");
}
```

Сохраните как `sys-pair.b`, примените команды выше с именем `sys-pair`.
Пример добавляет и затем снимает привязку внутри namespace эмулятора.
Оба вызова используют существующие C-обёртки. Конвертация обеих строк
выполняется до `release`; отказ первой или второй конвертации не входит в OS
и сохраняет ячейку результата. Проверки запускают GC между инструкциями и
на границе OS, меняют заимствованные аргументы после snapshot и проверяют
исходные строки, флаги и адрес результата. Публикация указателя аргумента
не создаёт факта инициализации числового результата.


## Управляемый FD как результат и аргумент

Явный файловый профиль также допускает `fildes(int): ref Sys->FD` и
`iounit(ref Sys->FD): int` через общий `$Sys` и сгенерированные native-входы.
Caller по-прежнему занимает 112 байт. FP96 отдельно владеет полноразмерным
указателем FD, а FP104 остаётся четырёхбайтовым числовым результатом.
Карта равна `00 88`, либо `00 c8`, если нужны оба строковых корня.
Оба callee имеют размер 72 байта: карта `fildes` — `00 00`, `iounit` — `00 80`.

Сохраните как `sys-fd.b`; команды выше применяются с именем `sys-fd`:

```limbo
implement SysFD;
include "sys.m";
SysFD: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    fd := sys->fildes(1);
    unit := sys->iounit(fd);
    saved := fd;
    fd = nil;
    unit = sys->iounit(saved);
    saved = nil;
    fd = sys->fildes(2);
    unit = sys->iounit(fd);
    fd = nil;
    status := sys->werrstr("FD calls completed");
}
```

Пример дублирует существующие дескрипторы эмулятора. Удаление последнего
локального алиаса очищает FD-корень и закрывает дубликат; завершение программы
также освобождает владельца. Ограниченный producer хранит одну текущую
FD-идентичность и её алиасы. Чтение прежнего алиаса после следующего `fildes`, `open` или `create`
отклоняется. Несколько независимых живых FD и общий доступ к полям ADT пока
не поддерживаются. Условные присваивания указателей сохраняют прежние
консервативные ограничения. Числовые аргументы можно заранее вычислить в Word.
Возврат FD из вызовов внутри ветвей и циклов работает, включая ноль итераций.

Приватная сигнатура содержит явное дерево ref/ADT с одним полем/int, а не
числовой результат или предположение о размере указателя. Приватные теги
`0x73`/`0x74` не являются публичными назначениями формата или общим допуском ADT.
Компилятор и загрузчик отдельно учитывают определённость FD и Word. Управляемый
результат не инициализирует FP104; публикация аргумента не определяет число.

Проверка владения выполняет настоящие `Sys_fildes`, `Sys_iounit`, `mkfd`,
`freeFD`, heap, collector, кадры и linker с контролируемой границей OS.
Проверяются замена, алиасы, последний nil, нормальное и ошибочное завершение,
откат до публикации и отказ выделения памяти после дублирования — как без
старого владельца, так и с ним. В полном эмуляторе `iounit(nil)` выбрасывает
прежнее исключение о неверном дескрипторе. Его обёртка теперь захватывает VM
перед повторным выбросом. Ошибочный результат не публикуется, владельцы
освобождаются. Эти две фиксированные сигнатуры ещё не включают общий файловый
ввод-вывод или полный запуск AWM.


## Открытие и создание файлов

Тот же путь управляемого результата допускает `open(string, int): ref FD`
и `create(string, int, int): ref FD`. Оба сгенерированных callee занимают
80 байт с картой `00 80`: путь находится по native-смещению 64, режим — 72,
права create — 76. В caller String хранится в FP64, FD-результат — в FP96;
они отделены от Word-локальных значений и FP104.

Сохраните как `sys-open.b`; команды выше применяются с именем `sys-open`:

```limbo
implement SysOpen;
include "sys.m";
SysOpen: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    fd := sys->create("/open-example.txt", Sys->OWRITE, 8r600);
    unit := sys->iounit(fd);
    fd = nil;
    fd = sys->open("/open-example.txt", Sys->OREAD);
    unit = sys->iounit(fd);
    fd = nil;
    status := sys->remove("/open-example.txt");
}
```

Запускайте в доступном для записи корне эмулятора, где путь примера свободен.
Файл создаётся, закрывается, открывается повторно, закрывается и удаляется.
Неудачный open/create возвращает nil; как и предыдущий ограниченный пример,
этот код предполагает успешное открытие перед `iounit`.

Строка конвертируется при удержанной VM до `release`. Существующие C-обёртки
сохраняют поведение замены владельца: очищают результат и освобождают старый
FD перед новой операцией. При ошибке native-открытия результат остаётся nil.
Если после успешной OS-операции отказывает `mkfd`, его настоящая очистка
закрывает новый дескриптор; старый уже освобождён. Частично созданный FD
не публикуется. Ограничение на текущий FD и его алиасы действует для всех
трёх создающих функций.

Права create — 32-битная маска Limbo. Преобразование через `UWORD` перед
передачей в native `ulong` сохраняет бит `DMDIR` без знакового расширения
на LP64. Проверка покрывает старший бит; контрольное удаление преобразования
обязано провалить сверку native-аргумента. Также проверяются оба числовых
смещения, ошибка Unicode-конвертации, успешная и неудачная замена, nil-путь,
циклы, алиасы, повторный load и все двенадцать импортов. Ограниченные байтовые read/write описаны ниже; общий запуск shell/AWM ещё не включён.


## Байтовые массивы и содержимое файлов

Общий путь `LOAD`/MFRAME/MCALL теперь допускает `read(ref FD, array of byte, int): int`
и `write(ref FD, array of byte, int): int`. Используются существующие C-обёртки
и сгенерированные интерфейсы Sys. Загрузка сама не вызывает `init`: точку входа
отдельно вызывает тестовый запускатель, как это делает оболочка.

Сохраните как `sys-bytes.b`:

```limbo
implement SysBytes;
include "sys.m";
SysBytes: module { init: fn(); };
init()
{
    sys := load Sys Sys->PATH;
    fd := sys->create("/bytes-example.txt", Sys->OWRITE, 8r600);
    b := array of byte "hello";
    n := sys->write(fd, b, len b);
    fd = nil;
    fd = sys->open("/bytes-example.txt", Sys->OREAD);
    b = array[20] of byte;
    n = sys->read(fd, b, len b);
    text := string b[:n];
    status := sys->werrstr(text);
    fd = nil;
    b = nil;
    text = nil;
    status = sys->remove("/bytes-example.txt");
}
```

Компиляция: `limbo -z -I module -64l -o /build/sys-bytes.dis64 sys-bytes.b`.
Запуск — приведённой выше командой эмулятора с `/sys-bytes.dis64`. Нужен корень
эмулятора, доступный для записи. Пример предполагает успешные операции и файл не длиннее
двадцатибайтового буфера. `werrstr` сохраняет прочитанный текст, но не
печатает его.

`array of byte text` кодирует строку в UTF-8, `string b` декодирует UTF-8.
Нулевые байты сохраняются в массиве; read/write получают явную длину.
`len b` считает байты, а не символы Unicode. Число байт ограничивается размером
буфера; nil и отрицательная длина обрабатываются существующими обёртками Sys.
Короткое чтение изменяет только возвращённый префикс. Преобразование всего
массива захватывает оставшийся хвост. После успешного чтения используйте
`string b[:n]`, чтобы преобразовать только прочитанный префикс. Ключ `-z` выбирает обнуляющую NEWAZ;
обычная NEWA не гарантирует обнуления байтов.

| Смещение в кадре вызывающего | Назначение |
| --- | --- |
| FP64 / FP72 | Корни первого / необязательного второго строкового аргумента |
| FP80 / FP84 / FP88 | Сохраняемые локальные Word |
| FP96 | Корень текущего FD, если он нужен импортам |
| FP104 | Результат Word, никогда не корень GC |
| FP112 | Корень текущего байтового массива |
| FP120 | Корень текущей преобразованной строки |

Кадр программы с массивами занимает 128 байт; разрешены точные карты
`00 83`, `00 8b`, `00 c3`, `00 cb`. Native-кадр read/write занимает 88 байт,
карта `00 c0`: FD и массив на 64/72, длина на 80. Третий сериализованный тип —
явный однобайтовый примитив с нулевой картой указателей. После проверки загрузчик
подставляет канонический `Tbyte` runtime до компиляции JIT. Приватные теги
структурной сигнатуры `0x75`/`0x76` обозначают массив/байт; публичному формату
эти значения не назначены.

Профиль допускает один текущий массив, одну текущую преобразованную строку и
один текущий FD, включая алиасы и освобождение последнего владельца через nil.
Замена меняет отслеживаемую идентичность: использование старого алиаса
отклоняется. Другие типы элементов, индексация массивов и произвольные ADT
остаются отдельной работой. Строковые аргументы и преобразованная строка имеют
раздельные корни, в том числе для двух аргументов `bind`/`unmount`.

Проверка runtime использует настоящие выделение массивов, UTF-8 преобразования,
C-обёртки Sys, GC и загрузчик в C-режиме и с запросом JIT. Проверяются короткое
чтение, ограничение записи, NUL, пустые буферы, замена владельцев, GC при release
и ошибки выделения без потери прежнего владельца. Повреждённые карты корней,
примитивные дескрипторы, сигнатуры и чтение неинициализированных Word
отклоняются. Контрольные внесения ошибок в доказательство array/Word и удаление
подстановки канонического байтового типа также должны проваливать проверку.


## Срез байтового буфера

`b = b[lo:hi]`, `b = b[lo:]` и `string b[:n]` теперь переводятся в существующую
инструкцию SLICEA. Границы — непосредственные целые или инициализированные
локальные Word, включая результат read. Пропущенная верхняя граница вычисляется
существующей инструкцией длины массива. Допускаются повторные и пустые срезы.
Границы считаются в байтах: для UTF-8 выбирайте позиции между символами,
не разрывая многобайтовую последовательность.

SLICEA меняет текущую идентичность массива. Только назначение среза становится
текущим поддерживаемым значением; использование старого алиаса после среза
отклоняется. Это ограничение данного профиля компилятора, а не общая семантика
алиасов Limbo. Оно действует и для временного среза `string b[:n]`: последующее
использование старого `b` пока не допускается. Его можно очистить через nil
или заменить новым массивом.

Загрузчик независимо проверяет, что массив и обе числовые границы
инициализированы на каждом входящем пути. Корни массива, строки и FD нельзя
использовать вместо границ. Затем исполняются существующие проверки диапазона
и времени жизни в VM. Уникальный байтовый массив сужается без выделения нового
заголовка. Если общий владелец требует заголовка представления, отказ выделения
сохраняет прежний массив. Выход за границы также не публикует новое назначение.
Проверка runtime покрывает оба отказа; контрольное удаление требований
инициализации массива и границ обязано приводить к обнаружению повреждённых
образов.

При передаче среза в write его основа остаётся жива при GC во время release.
Консольные примеры покрывают чтение префикса, средние и конечные срезы,
повторные срезы, пустые буферы и UTF-8 в C-режиме и с запросом JIT. Новых
полей формата и номеров инструкций нет; произвольные типы элементов не включены.
