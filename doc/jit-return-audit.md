# RET bridges that survive returning-module destruction

## Native continuation lifetime

The final module reference can be released by VM ret. The generated fallback
called that VM operation and then continued executing its punt sequence inside
the module being returned from. If ret unloaded the module, the native return
address pointed into freed program memory. The old native reference-count
check selected exactly this fallback for the last-reference case; it did not
make the helper's native continuation safe.

Both backends now put the RET body in the process-lifetime comvec allocation.
Each module's MacRET is only a jump to that body. IA-32 uses its full rel32
address space; ARM loads an absolute A32 target through the literal pool, so
the bridge need not be near the module. The RET body and permanent reclaim
thunk are published only after the shared block's cache synchronization.
Capacity is now 1024 bytes on IA-32 and 512 words on ARM; only generated bytes
are flushed. Existing compilation rollback owns unpublished allocations.

The IA-32 RET emitter now resolves its local branch patches in a single
emission, without static offsets left over from a prior pass. Short-branch
range is checked explicitly. This is needed when emitting the shared preamble
once, and also makes the result independent of the preceding compilation.
Synthetic RET fallback instructions are zero-initialized on both backends.

## Retain the module through frame destruction

The former cross-module fast path decremented the current Modlink reference
and switched R.M before invoking the frame Type destructor. A pointer in that
frame could hold another reference to the returning module. Dropping it could
then unload the module and its Types while destruction was still executing.

Cross-module returns now use VM ret through the permanent bridge. Its existing
order frees frame pointers while the current module reference is still held,
then releases that module and restores the parent. Same-module ordinary
returns keep a native Type-destruction/unwind path. Nil Type/destroy, root
frames and stack-extension frames use the established VM fallback.

This deliberately gives up the cross-module RET optimization. The module
entry wrapper also adds a jump. Performance has not been measured.

## Checked module spawn

mspawn still performed its own unchecked int-width link/export lookup after
creating a Prog. It now uses the same full-WORD modulelink resolver as mcall
and mframe, rejects nil/H entry addresses, and only then creates the child.
Invalid references therefore cannot publish a child or consume its stack.
Nil module and runtime-module exSpawn behavior are retained. Stack allocation
failure after child creation remains a separate audit area; this change does
not claim a fully transactional spawn implementation.

## Executed checks

```
python3 libinterp/tests/jit-returns.py
python3 libinterp/tests/module-links.py
python3 libinterp/tests/x86-publish.py
python3 libinterp/tests/arm-publish.py
```

- jit-returns executes the real shared preamble, module MacRET wrapper, RET
  body and helper bridge in 144 IA-32/ARM cases. It covers same-module and
  cross-module returns to native/interpreted parents, one/shared module refs,
  missing Type/destroy, root fallback and volatile-register clobbers. The VM
  callback unmaps the actual module code page before returning in last-ref
  cases; its native continuation must remain executable. Native module refs
  must still be held on entry to the VM callback. Register/PC/stack outcomes
  and unchanged Frame headers are checked. Actual Type/VM RET bodies are
  simulated; root errors stop at the callback boundary.
- The shared preamble and real reclaim thunk remain covered by jit-lifetime.
  Its preamble RET body is a return stub; jit-returns covers the real body.
  Publication/rollback tests now inject 53 IA-32 and 51 ARM event failures,
  including RET emission, and assert paired permanent-pointer publication.
  Existing allocation/cache failures, retries, table mutations and Type
  rollback remain covered. Their RET emitter is an event-recording boundary.
- module-links now runs 196,662 checks per WORD32/WORD64 operand model
  (393,324 total). In addition to prior link/runtime/linker coverage, mspawn
  invalid indices and nil/empty exports must leave child/stack/unframe counters
  untouched. Valid imports/exports check the selected child PC. Runtime-module
  rejection is checked. Actual VM ret is exercised with a frame-held module
  reference: pointer destruction must precede the final module release, for
  native/interpreted parents. Root RET errors preserve the pending Frame.
  Prog creation, stack creation and GC release are recording bodies; Proc
  error frames and the tested VM operation bodies are production code.

Separate negative controls generated a module-owned RET body and reproduced
an unmapped instruction fetch after module removal on each architecture.
An early-reference-release mutation fails the frame ownership assertion.
Restoring the old mspawn body fails the spawn/link-state checks.

These are host-emulation and extracted-runtime tests, not an OS boot or a
full native C ABI/GC/unloader integration test. They use projected IA-32/ARM32
native layouts and host runtime layouts with WORD32/64 operands. Hardware
cache coherence, executable-memory permissions, complete stack ownership and
allocation-error cleanup remain outside this proof. No 64-bit ABI is enabled.

All 34 libinterp Python suites pass. The RET suite also passes under
__ARM_ARCH=4; full xec/IA-32/ARM syntax checks pass with Linux headers.
