# Native64: составные ответы Wmlib

Добавлены три свежих результата внешнего CALL/MCALL, используемых оконным
клиентом. Обычный Dis и 32-битный код не меняются.

| Контракт | Тип результата | Classic/native размер | Native GC roots |
| --- | --- | --- | --- |
| 80 | `(string, int)` — qword | 8/16 | 0 |
| 92 | `(Draw.Rect, int)` — s2r | 20/20 | нет |
| 124 | `(string, ref Draw.Image, string)` — wmctl | 12/24 | 0, 8, 16 |

Compiler проверяет точные nominal Draw типы, каждый scalar/root лист,
classic/native смещения и размер результата. Частная аннотация 85
обозначает свежую привязку результата к FP. Иные числовые/корневые формы,
глобальный результат и inherited результат остаются закрыты.

До трансляции инструкций план кадра резервирует C padding составного
результата. Для String/int это существенно: последующие locals не должны
попадать в последние четыре padding байта C структуры. Сдвиг кратен восьми,
поэтому следующие roots сохраняют выравнивание. Уже имеющийся зазор
учитывается: повторное использование одного временного tuple не расширяет
кадр снова. Formal arguments нельзя использовать как область результата.

Module builder проверяет единственную enclosing call-site, совпадение
контрактов caller/import, запрет inherited, точную карту каждого байта
результата и границы кадра до выделения памяти. Частный materializer
повторно проверяет форму привязки. Runtime LEA перед выдачей адреса
проверяет реальную карту и размер caller frame, pending callee и выбранный
контракт. Новые формы не расширяют FileIO/channel контракты.

## Проверка

Расширен существующий `native64-wmclient-geometry.py`, уже включённый в
native64-port и оба native64-typed-calls CI задания. Fixture содержит 91
проверенное тело и канонические import frames из Draw/Tk/Wmlib headers.
Добавлены отдельные потребители qword, s2r и wmctl, а также повторные qword
вызовы с общим временным результатом. Wmlib здесь — контролируемые сервисы,
проверяющие точные строковые/числовые аргументы; исходные реализации
парсеров Wmlib в этом тесте не исполняются.

Выполняются 4392 C/JIT вызова с квантами 1/3/1000. Проверяются все восемь
комбинаций nil/non-nil String/Image/error, крайние int, exact Rect/Window
neighbors, refcounts и полное освобождение. Контролируемый qword пишет
не только полезные поля, но и все четыре padding байта: соседний local
обязан сохраниться. Исполнение старых четырёх исходных методов Window и
всех прежних геометрических путей сохраняется.

Независимый oracle обнаруживает 522 изменения инструкций, одновременно
сравнивая classic bytes. Metadata gate отвергает 631 искажение до
выделения, включая 87 map controls и отдельные нарушения caller/import
контрактов. Конструктор проверяется на 224/225 точках отказа C/JIT.
Четыре активных контроля включают неверный адрес tuple результата.

На amd64 прошли UBSan и ASan/UBSan (detect_leaks=0, собственный полный
retirement включён), регрессии geometry/local geometry, Window fields,
Window arguments, Wmsrv и AWM, а также чистая console сборка с pair и
emuinit boot. Локальные arm64/riscv64 прогоны в этом блоке не выполнялись.

## Точная граница прогресса

Полный исходный Wmclient сохраняет 9/21 принятых тел. Отказ wmctl сдвинулся
с tuple результата qword на подготовку String slice/concat аргумента
Titlebar.sendctl (PC 511), а wmreq — с tuple результата на подготовку
variadic fprint с Window.ctxt.connfd (PC 666). Следующий связанный блок —
подготовка этих аргументов, head list в startinput и оставшиеся image/cursor
вызовы. Настоящее окно AWM и Android GUI ещё не запущены.

Следующий блок подготовки аргументов описан в
[native64-call-prep.ru.md](native64-call-prep.ru.md).
