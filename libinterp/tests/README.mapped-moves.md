# Typed VM record moves and channel transfer

Run `python3 libinterp/tests/mapped-moves.py` from the repository root.
`CC` and `CFLAGS` select the host compiler and flags; UBSan is enabled by default.
`MAPPED_MOVE_SOURCE` selects an alternate `libinterp/xec.c`.
`MAPPED_MOVE_CASE=overlap`, `mixed`, `buffer`, `direct` or `empty` selects a group.

The fixture extracts production `movtmp`, `movmp`, module type resolution,
reference retention/release, array creation/initialization/destruction, buffered
channel get/put, direct send/receive and queue removal. Real interpreter records
supply their native layouts. Exact guarded allocation, child destruction and
scheduler transitions are bounded adapters. There is no full VM boot, real
concurrent scheduler or target JIT execution.

Each WORD64/WORD32 model runs 12,477 checks, or 24,954 executions. WORD32 retains
native host pointers, and explicitly requires the descriptor address to exceed
32 bits in that model. This reproduces the truncation caused by reading native
channel metadata through W(m). `movtmp` now reads a native Type pointer directly;
no VM scalar width or generated bytecode ABI changes.

The overlap matrix snapshots the source independently and covers widths one
through eight pointer slots, all source/destination placements, exact aliases,
both overlap directions and shared children. External child owners let a separate
reference-count oracle inspect every child, even when its record owner vanished.
Mixed records verify nil/populated pointer fields, signed/high-bit numeric values,
unchanged source bytes and padding. Real incmem/freeptrs must retain all source
owners before replacing destination owners.

Typed FIFO cases fill/drain capacities one through eight from every initial ring
position, repeatedly replacing nonempty output records and checking wraparound,
order, full/empty results and cleared buffer pointer slots. Direct send/receive
cases run real isend/irecv against a queued peer and check pointer cleanup, wakeup
and multi-field reference ownership. They exercise actual movtmp; earlier channel
matrices primarily exercised scalar/pointer movers.

Zero-sized mapped records are no-ops after descriptor resolution. They must not
call memmove on nil/VM-nil data addresses. Empty typed messages also circulate
through real zero-byte array buffers. Invalid module indices still raise before
the zero-width optimization, so metadata resolution is not bypassed.

The full matrix passes UBSan and ASan+UBSan with stack instrumentation enabled:

```
CFLAGS='-O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all' python3 libinterp/tests/mapped-moves.py
```

Every heap/array/type/child reference and allocation guard is checked explicitly;
LeakSanitizer process inspection is unavailable. The sandbox's stack-bound warning
occurs on the expected module error, but the complete fixture passes without
manual stack unpoisoning or disabling instrumentation.

Parent substitution completes the WORD64 overlap matrix, then fails on WORD32's
truncated descriptor. The empty-record subset independently reports UBSan's null
memmove argument in the old implementation. Native pointer-width and full 64-bit
ABI/JIT acceptance remain separate from these host word models.

Use `python3 libinterp/tests/slice-tokenize-suite.py --core` for the focused VM /
compiler checkpoint. It includes this driver and module type consumers and omits
GUI/Tk and launcher-option tests. `--jit` can additionally select the existing
x86/ARM instruction-emulation drivers when their dependencies are installed;
those optional JIT checks are not claimed by this series.

Buffered receives now retain the buffer across movement and consumed-slot cleanup.
The destination may own the last channel reference; destroying that channel must
not invalidate the message being copied or its subsequent pointer cleanup. When
a sender is waiting on a full buffer, irecv separately retains the channel until
the received slot has been refilled. This keeps both its metadata and buffer
alive until the sender's payload has been transferred.

The extended matrix runs 13,917 cases per model (27,834 total). Its 1,440 new
borrowed-channel cases cover mapped records of one through eight pointers, every
channel-owner slot, capacities one through four, every initial ring position,
sole/shared channel owners and receives with/without a waiting sender. Production
irecv, cgetb/cputb, movtmp, heaparray, reference maps and freearray participate;
the bounded destruction adapter releases real heap channel buffers and descriptor
references. Full output, wakeup counts, refill sizes, exact child references and
all heap/type balances are checked. Both models pass the complete ASan+UBSan suite
with stack instrumentation enabled.

The old cgetb body reproduces a message-buffer heap-use-after-free. Substituting
only the corrected cgetb into the parent source independently exposes irecv's
missing channel owner during refill. Run just the new matrix with
`MAPPED_MOVE_CASE=borrowed`. Queue/scheduler boundaries remain modeled, not native
concurrent threads. No complete VM boot, GC cycle or target JIT execution is
claimed. Tk, security/cryptography and backend sources are unchanged.

[Mapped copy callback captures](README.mapped-capture-native.md) verify that
MOVMP, HEADMP and movtmp keep their original source/result addresses when old
field destructors borrow REG, including complete AMD64 JIT fallback entries.
