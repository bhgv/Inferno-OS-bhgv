# Sys.file2chan capture, construction and native message layouts

Run `python3 libinterp/tests/sys-file2chan-capture.py` from the repository root
for the complete frame/callback and early-rejection matrices. The lower-level
`sys-file2chan.py` retains its original layout/normal/wide selectors. Both drivers
use ASan/UBSan and `NDEBUG` by default. Explicit predicates remain active;
`CC` and `CFLAGS` can override the compiler and flags.

Both production implementations copy the complete fixed call frame with
`sysstatusframe` and validate/capture the previous result with `sysresultowner`
before string conversion, allocation or registration. Unaligned borrowed call
frames and result slots are read or published with byte copies. The original
result address and old owner are retained through all callbacks. Both channels
must finish construction before registration; exceptions roll back the partial
pair and restore VM ownership and the error string. Publication precedes
finalization of the captured old result. Ordinary registration errors preserve
the existing nil-result convention; exceptions preserve the caller's result.

The owner preflight rejects nil, low, unaligned and zero-reference old owners.
It checks numeric spans and ownership metadata, not arbitrary address mapping,
complete object extents or a FileIO type tag. Generated bytecode constants and
the public function signature are unchanged.

The fixture executes real heap/type constructors and finalizers, pointer maps,
channel queues and buffers, string/UTF conversion and cache cleanup, production
error protection and both platform/service initializers. Exact guarded native
allocation, scheduler boundaries and registration are adapters. All VM errors
run on a joined pthread's real stack, allowing complete ASan fault coverage
without disabling stack instrumentation or manually unpoisoning memory. LSan
process inspection is unavailable; explicit block and type-reference accounting
checks every scenario.

For each emu/os and WORD32/WORD64 build:

- The capture matrix executes 123,648 scenarios: seven phases, eight frame
  shifts and eight result shifts, ASCII/UTF paths, nil/previous results, success,
  returned native errors, native exceptions, and every allocation failure by
  nil return and by exception. Phases cover an unchanged frame, frame mutation
  during allocation/release/registration/acquire/old finalization, and clearing
  the old result slot during allocation. The last phase independently checks
  that destruction uses the captured old owner rather than rereading the slot.
- The preflight matrix executes 640 early failures: ten bad-frame/result/owner
  cases across all eight frame and result shifts. It checks unchanged complete
  buffers and guards, no native call or allocation, balanced error/VM state,
  and unchanged previous-owner and aliased-channel reference counts.
- Each build also performs one unconditional descriptor-layout scenario.

Totals are 494,592 capture scenarios and 2,560 preflight scenarios, plus eight
layout scenarios. The original lower-level default matrix remains 2,208 ordinary
scenarios plus one layout scenario per build (8,836 executions in four builds).
WORD32 retains native host pointers and uses host emulator error frames; it
is not a complete 32-bit target ABI or a real ARM64 boot test.

`FILE2CHAN_SOURCE` and `FILE2CHAN_SERVICE` select alternate production sources.
`FILE2CHAN_PLATFORM=emu|os` and `FILE2CHAN_WORD=32|64` select one build.
`FILE2CHAN_CAPTURE=1` enables the enlarged matrix;
`FILE2CHAN_PHASE=0..6` and `FILE2CHAN_FRAME=0..7` isolate one phase/frame shift.
`FILE2CHAN_PREFLIGHT=1` selects early rejection and `FILE2CHAN_MODE=0..9` can
isolate one bad-input family. `FILE2CHAN_CASE=layout|normal|wide` retains the
original selectors.

All 64 independently compiled controls against parent `275bc64` fail with an
active predicate or sanitizer diagnostic: four builds times a packed-frame
probe, five callback/owner probes and ten preflight probes. No compile failures
count as regression evidence.

Native registration is simulated atomically. The fixture does not test service
permissions, filesystem lookup/publication, concurrent clients, real scheduler
concurrency, a kernel build, or complete native JIT/ABI support.
