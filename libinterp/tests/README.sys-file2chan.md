# Sys.file2chan construction and native message layouts

Run `python3 libinterp/tests/sys-file2chan.py` from the repository root.
`CC` and `CFLAGS` select the compiler and flags; UBSan is enabled by default.
`FILE2CHAN_SOURCE` selects an alternate platform `inferno.c` and
`FILE2CHAN_SERVICE` selects its `devsrv.c`. `FILE2CHAN_CASE=layout` checks only
the descriptors; `normal` checks successful calls and returned native errors;
`wide` isolates UTF path-cache allocation during successful registration.

Production bodies include both platform initializers, FileIO finalization and
construction, runtime error protection, heap/type creation, pointer maps, array
initialization/release, the full channel constructor, string/UTF conversion and
cache release. Actual native FD and generated Sys record declarations provide
their C layouts. Exact guarded allocation, scheduler transitions and native
registration are bounded adapters. Registration is simulated atomically and does
not retype channels or exercise the service's permission checks, filesystem
lookup, publication or concurrent clients.

Each emulator/kernel and WORD32/WORD64 configuration executes 277 scenarios,
for 1,108 executions. WORD32 retains native host pointers; both sources use host
emulator error-frame declarations. The tests do not establish a complete target
ABI, kernel build or native JIT run. Generated bytecode constants are unchanged;
real 32-bit native layouts retain their established sizes and pointer positions.

Descriptors use native `sizeof` values for FileIO, read/write requests and
read/write replies. Pointer positions are computed from native field offsets.
This matters especially for a WORD32 request with three word fields followed
by an eight-byte channel pointer. Tests check descriptor sizes and actual mapped
initialization of every pointer in both sixteen-entry request rings and reply
records. Poisoned scalar/padding bytes make wrong maps observable.

Each allocation is failed in turn, once by returning nil and once by throwing
before allocation. Cases include both channel heads, queues and buffers, UTF
path caches, nil/previous results, a previous result whose channels alias, native
registration failure and an unexpected native exception. Every exit must balance
scheduler/error frames, heap blocks, type references and guards. Old results
survive VM exceptions; ordinary native errors retain the existing nil-result
convention. Destruction adapters can overwrite the error string, so cleanup must
restore the original error. Input string conversion must occur while the VM is
acquired; registration must occur released.

The full matrix passes UBSan and explicit ownership/guard checks. LeakSanitizer
inspection is unavailable; every allocation, including caches and descriptors,
is counted and released. Successful and returned-native-error paths pass ASan
with stack instrumentation enabled:

```
FILE2CHAN_CASE=normal CFLAGS='-O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all' python3 libinterp/tests/sys-file2chan.py
```

Full ASan fault coverage is not claimed in this sandbox: nested nonlocal jumps
produce ASan's unavailable-stack-bounds warning followed by a stale stack-shadow
report. Stack instrumentation is not disabled or manually unpoisoned. A host
with working stack-bound inspection is needed to complete that verification.

Parent-source probes reproduce a nil/undersized FileIO descriptor directly.
Replacing only parent layout initialization isolates its released-VM UTF cache
allocation and leaked partial FileIO/channel construction. Adjacent channel,
directory, descriptor-owner and combined checkpoint suites provide regression
coverage for the surrounding runtime.
